## 1. 环境：用哪个 python

| 场景 | 用什么 | 原因 |
|---|---|---|
| **沙箱 / CI / 本手册** | `.venv/bin/python` | 沙箱里 `uv run` 会失败（`Failed to initialize cache at ~/.cache/uv: Operation not permitted`） |

## 4. 逐个命令：怎么看结果

### 4.1 `audit_corporate_actions.py` —— 这张表在问："价格序列干净吗？"

```bash
.venv/bin/python scripts/audit_corporate_actions.py            # 只看登记在册的 17 个标的
.venv/bin/python scripts/audit_corporate_actions.py --all-cached   # 连带磁盘上所有 equity 缓存
```

**输出四段**：① 逐标的表 → ② 检测到的断崖事件明细 → ③ 结论计数 → ④ 已知局限。

逐标的表的列：

| 列 | 含义 | 怎么读 |
|---|---|---|
| `根数` | 有效日线根数 | ETF 正常 400~1800 根 |
| `原始最大` | **未复权**序列的最大单日涨跌幅 | **>22% 就是企业行为**（份额折算/拆分），不是行情 |
| `复权后` | 复权后的最大单日涨跌幅 | 应该 ≤20%（涨跌幅限制） |
| `97后最大` | 1997 年后的最大（用于残余检验） | 见下方"残余可疑" |
| `法定` | 该代码的法定涨跌幅上限（启发式） | 主板 10% / 双创 20% / 北交所 30% |
| `状态` | ✅无断崖 / 🔧已修复 / ⚠️残余可疑 / ❌失败 | 只有 ❌ 会让退出码变 1 |

**当前基线**（2026-10-04）：

```
✅ 无断崖: 4   🔧 已修复: 13   ⚠️ 残余可疑: 3   ❌ 失败: 0        ← exit 0
```

**怎么读这三类**：

- `🔧 已修复`：检测到断崖并**自动前复权**了。例如
  `sh512480 2021-03-29 前收 1.7340 → 收 0.8860（−48.90%）` —— 这是 1:2 份额折算。
  **修复是自动的、在读出时进行**；缓存里存的**始终是原始未复权价**（所以改口径不用重刷缓存）。
- `⚠️ 残余可疑`：复权后仍有超过"法定上限"的单日变动 ⇒ **疑似有一处小于 22% 阈值的送转没被识别**。
  当前 3 个：`sz002371`（主板 ±10%，却有 21.95%）、`sh600641`（16.51%）、`sh603690`（17.35%）。
  **影响面**：ETF 全部通过 ⇒ 不影响 Phase 2 的结论（信号用指数、执行用 ETF）；
  只在**合成主题指数（P0.4c）**时才必须解决 —— 那一步要改用带复权的数据源（baostock 支持 `adjustflag`）。
- `❌ 失败`：复权后仍 >22% ⇒ 该标的可能**没有涨跌幅限制**（跨境 ETF / 退市整理股）或阈值不当。
  **必须人工复核**，不许静默通过。

> **为什么这个门禁最重要**：腾讯 ETF 日线**不含复权**。不修的话，
> 两只几乎同质的半导体 ETF（512480 vs 512760）日收益相关性会从 **0.990 掉到 0.666**，
> 于是"指数 vs ETF 相关性 ≥0.8"这条验收会把**达标的东西判成不达标**。

### 4.2 `audit_theme_index.py` —— 这张表在问："用哪条价格序列代表这个主题？"

```bash
.venv/bin/python scripts/audit_theme_index.py          # 报告模式（exit 0）
.venv/bin/python scripts/audit_theme_index.py --gate   # 门禁模式（当前 exit 1）
```

**判据**（两条都要满足）：**指数历史 ≥10 年** 且 **与对应 ETF 的日收益相关性 ≥0.8**。

逐主题表的列：

| 列 | 含义 | 怎么读 |
|---|---|---|
| `根数` / `年数` | 主题指数有多少历史 | <10 年 ⇒ 判据 1 不达标 |
| `重叠` | 与 ETF 的共同交易日数 | 决定相关性可不可信（<200 就别当回事） |
| `corr` | **全重叠**日收益相关性 | **<0.8 ⇒ 这条指数不能代表该主题** |
| `c500` | **近 500 日**相关性 | 与 `corr` 差距大 ⇒ 近期脱钩 |

**当前基线**（2026-10-04）：

```
✅ 可用（现成指数达标）: 14 项 → 半导体设备 / 半导体设备材料 / 芯片
                                  （三者 2026-10-04 换用 sh000039 上证信息，最小相关性 0.835）
                                  / 云计算与大数据 0.873 / 消费电子 0.906 / 黄金 0.844
                                  + 观察项：红利 0.973 / 电力 0.964 / 有色 0.988 / 煤炭 0.988
                                    / 银行 0.983 / 军工 0.975 / 创新药 0.964 / 机器人 0.949 / 证券 0.994
❌ 需合成指数:          1 主题 → 电网设备（0.686；所有候选最好只有 0.777）
⚠️ 降级/受限:           3 主题 → 第三代半导体(无 ETF) / 科创半导体 0.847 / 科创创业50 0.909
                                 （后两个只有 6.7 年，用户已决定接受）
```

**三种判定怎么读**：

- `✅ 可用` ⇒ 这条指数**可以**用于 Phase 2 的收益验证。
- `❌ 需合成` ⇒ **不许**用它的现成指数做验证（否则你验证的不是这个主题）。
  "半导体设备"是主线却被判 ❌，这是本轮最扎心的发现。
- `⚠️ 无 ETF` ⇒ 没有执行载体，相关性无法校验 ⇒ 按 kill criterion 5 **只显示、不验证**。
- `⚠️ 历史不足` ⇒ 判据 1 不满足，已记录在案并接受。

> **为什么 --gate 返回 1 是对的**：它把"3 个主题的标的不合格"编码成了门禁。
> 你要救它们，就该去做 P0.4c 合成指数，**而不是**把门槛从 0.8 调到 0.7。

### 4.3 `audit_theme_signals.py` —— 这张表在问："这信号一年来几次？"

```bash
.venv/bin/python scripts/audit_theme_signals.py
```

**口径**：**片段数（episodes）/ 年**，不是天数 —— 相邻（索引间隔 ≤3 日）为真的日子合并成 1 段。
这与仓库里"恐慌择时 33 个片段 / 10 年 ≈ 3.3 次/年"是同一口径。

**窗口纪律**（写在表头，很重要）：

```
预热        < 2016-01-01                ← 均线/摆动点需要历史，只作预热
主窗口 A+B  2016-01-01 ~ 2023-12-31     ← 本脚本只统计这里
🔒 OOS      2024-01-01 ~ 2026-09-30     ← 一行都不算（只看一次的机会要留着）
```

**当前基线**：

| 层 | 次/年 | 怎么读 |
|---|---|---|
| **L1 单层** | **4.8 ~ 5.0** | ✅ 与 PANIC_DOWN 的 4.4 次/年可比，够用 |
| L2 单层 | 1.4 ~ 2.1 | ⚠️ 偏少 |
| RS（状态） | 6.1 ~ 8.5 | 状态占比 27~38% |
| **L1+L2（同日 AND）** | **0.00 ~ 0.88**（中位 0.75） | ❌ **全部低于 kill 线 2 次/年** |
| L1+L2+RS | 0.25 ~ 0.63 | ❌ 同上 |

表尾还有两段特别重要：

- **【状态天数占比】**：L1 约 18~20%、RS 约 27~38% —— 提醒你 L1/RS 是**状态**（会连续多日为真），
  L2 是**事件**（上穿当天，1 天）。
- **【独立价格序列】**：**10 个主题只有 5 条不同价格序列**
  （`sz399363` 被 4 个主题共用）⇒ "10 个主题都验证一遍"是**假的独立复现**，
  多重检验压力要按 **5** 算。

> **为什么 --gate 返回 1 是对的**：联合层坍缩到 <1 次/年，触发预注册的
> **kill criterion 3**（<2 次/年 ⇒ 不进入仓位逻辑，只做观察）。
> **不许**为了救频次把"同日 AND"放宽成"N 日内共现" —— 那是改冻结项。

### 4.4 `audit_theme_returns.py` —— 这张表在问："它到底有没有用？"

```bash
.venv/bin/python scripts/audit_theme_returns.py                          # 只用主判据 H=20（快）
.venv/bin/python scripts/audit_theme_returns.py --holds 5,10,20,40       # 加持有期敏感性（慢 3 倍）
.venv/bin/python scripts/audit_theme_returns.py --index sz399363         # 只看一条序列
```

**统计口径**（写在表头）：

```
观测   fwd20(i) = 第 i 日**次日开盘**入场、持 20 根**收盘**出场（%）
D      mean(fwd20 | 掩码内) − mean(fwd20 | 掩码外)     （pp）
SE     块长 20 的移动块 bootstrap（避免重叠窗口高估显著性）
t      D / SE
MDE    2.80 × SE     ← 注意：这让门槛实际变成 |t| ≥ 2.8，比 1.96 更严
placebo 片段匹配重采样 p（保持片段长度分布，单尾）
```

逐序列表的列：

| 列 | 含义 | 怎么读 |
|---|---|---|
| `片段` | 信号片段数 | **<10 个就别看后面了**，什么都不可能显著 |
| `信号天` | 掩码为真的天数 | 大而`片段`小 ⇒ 长时间处于该状态 |
| `D(pp)` | 效应（百分点） | 正=该状态下持有更好 |
| `SE` / `t` | 标准误 / t 值 | 判据 1：`\|t\| ≥ 1.96` |
| `MDE` | 最小可检测效应 | 判据 2：`\|D\| ≥ MDE`（这才是真正的门槛） |
| `p_boot` | 块 bootstrap 的 p | 辅助看 |
| `plc_p` | placebo p | 判据 4：`< 0.05` |
| `A段D` / `B段D` | 分体制效应 | 判据 3：**两段必须同号** |
| `同号` | ✅/❌ | 段间不一致 ⇒ 体制依赖，不采用 |

**当前基线（主判据 H=20，按去重后的 5 条序列）**：

| 指数 | 主题 | 片段 | D | t | MDE | 判定 |
|---|---|---|---|---|---|---|
| `sh000039` | 半导体设备/材料/芯片/第三代 | 36 | +1.35pp | +1.00 | 3.78 | ➖ 未通过 |
| ~~`sz399363`~~ | ~~同上（2026-10-04 前的旧指数）~~ | 40 | −0.50pp | −0.42 | 3.20 | ➖ 已弃用 |
| `sh000998` | 云计算与大数据 / 消费电子 | 39 | +1.09pp | +1.00 | 3.12 | ➖ 未通过 |
| `sz399808` | 电网设备 | 40 | +4.29pp | +3.16 | 3.71 | ⚠️ **通过但标的不可用** |
| `sh000015` `sh000937` `sh000819` `sz399998` `sz399986` | 5 个**观察项**（红利/电力/有色/煤炭/银行） | 31~48 | 见 `--json` | — | — | ➖ 仅观察，**不进结论** |
| `sh000688` | 科创半导体 / 科创创业50 | 19 | −1.19pp | −0.78 | 4.52 | ➖ 未通过 |
| `sh000819` | 黄金 | 38 | +0.40pp | +0.30 | 3.85 | ➖ 未通过 |

**怎么看结论**：

- `➖ 未通过` 有两种含义，**必须分清**（表尾"判定"列会写原因）：
  - `|t| < 1.96` **或** `|D| < MDE` ⇒ 多半是 **"不可判定"（样本不够）**，**不是"已证明无效"**；
  - `两段不同号` ⇒ 结论**体制依赖**，不可采用。
- `⚠️ 通过但标的不可用`：`sz399808`（中证新能）确实有效，但它与电网设备 ETF 相关性只有
  0.686 < 0.8 ⇒ 按 **kill criterion 5 该主题不参与结论**。**这是本轮唯一"好看"的一格，而它不算数。**
- **排除该序列后**，L1 的加权效应是 **+0.14pp（1283 个信号日）** ⇒ 实质为零。
- `【持有期敏感性】` 段是**描述性**的：H 换成 5/10/40 只是让你看稳不稳，
  **不参与通过/不通过**（主判据在冻结时已固定为 H=20，事后挑最好的 H 就是多重检验）。

> 与半导体 ETF 同步不代表它代表"半导体设备"。

### 4.4c 观察项（`WATCH_ONLY`）—— 想多看几个 ETF 怎么办


## 5. 术语表（看懂上面所有表的关键）

| 术语 | 一句话解释 |
|---|---|
| **L1 / L2 / RS** | 三个独立的择时布尔层：结构破坏 / 均线转向 / 相对强度 |
| **掩码（mask）** | 每个交易日一个 True/False，表示该层当天是否成立 |
| **片段（episode）** | 把连续为真的日子合并成 1 段；**频次的分母口径是"段"不是"天"** |
| **D** | 效应 = 掩码内平均收益 − 掩码外平均收益（pp） |
| **MDE** | 最小可检测效应 = 2.80 × SE（α=0.05 双尾 + 80% 功效）。**`\|D\| < MDE` 时结论是"不可判定"，不是"无效"** |
| **placebo** | 安慰剂：把信号片段随机挪到别的日子，看原效应还稀不稀奇（`p<0.05` 才算） |
| **块 bootstrap** | 把连续 H 天当一块整体重采样，解决"相邻两天的 20 日窗口重叠 19 天"导致的假显著 |
| **A 段 / B 段** | 2016-2020 / 2021-2023。**两段同号**才敢说不是单段拟合 |
| **🔒 OOS 段** | 2024-01-01~2026-09-30，**只在样本内通过后才允许看一次**；目前**未动用** |
| **kill criteria** | 预注册的"什么情况下必须放弃这个假设"，到点就必须执行，不许事后放宽 |
| **前复权** | 把企业行为（份额折算/拆分）造成的断崖修平，让收益连续可算 |

## 6. 六个最容易误读的地方（先看这个，能省大量时间）

| # | 误读 | 真相 |
|---|---|---|
| 1 | "`audit_theme_index.py --gate` / `audit_theme_signals.py --gate` 返回 1，环境坏了" | **不是**。这两个 1 就是本轮的**研究结论**（3 个主题标的不合格 / 频次不足）。它们不是健康门禁 |
| 2 | "观察哨点亮了 L1，是不是该买？" | **不是**。`validated=False`：L1 在 4 条有效序列上 `t` 只有 −0.42~+1.00。**只显示、不决策** |
| 3 | "未通过 = 证明没用" | 多半是 **"不可判定"**：MDE 3~4.5pp，而目标效应量级是 +2pp（`进化路径.md`：检出 +2pp 需 **149 轮**，我们每条序列只有 19~40 个片段） |
| 4 | "10 个主题 = 10 个独立证据" | **不是**。只有 **5 条**不同价格序列，`sz399363` 被 4 个主题共用 |
| 5 | "`sz399808` 那格 D=+4.29pp、t=+3.16，这不就是有效吗？" | 它是**中证新能**的指数，与电网设备 ETF 相关性只有 0.686 ⇒ 按 kill criterion 5 **不参与结论** |
| 6 | "ETF 价格直接用就行" | **不行**。腾讯 ETF 日线**未复权**（512480 在 2021-03-29 单日 −48.90%）。一律走 `core.marketdata_tx.fetch_equity_history`（默认 `adjust=True`） |
