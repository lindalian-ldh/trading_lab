scripts/run_leader_pipeline.py 实现说明

实现说明

创建 scripts/run_leader_pipeline.py，把原本需手动串接的链路自动化：

bankuai 扫龙头 → calc_indicators 批量筛查 → 按通过维度过滤 → yanbao/sell_monitor 衔接 → 龙头池沉淀回 stock_mapping.json

设计取舍

  • bankuai / yanbao-info / PNG 报告：用 subprocess 调 CLI（要拉 zzshare/PDF，重，且 CLI 自带 token/env 处理）
  • calc_indicators 筛查：同样用 subprocess + 正则解析稳定输出（一开始试过 in-process 调 _evaluate_stock，但 calc_indicators 的 config.py 与项目根 config/ 包命名冲突被 core.logger 提前缓存遮蔽；subprocess 方案与 run_all.py 风格一致，且不被内部 API 变更影响）
  • sell_monitor：只打印登记命令不自动登记——系统是纯信号，进场需人确认 entry-price

参数速查

参数 默认 控制场景
--date昨天参考日期
--plate-type概念板块类型 概念/题材/行业
--sectors空指定板块名（逗号分隔），非空仅扫这些
--top-n-sectors3热门板块取前 N 作为龙头池来源
--tierstier1,tier2参与筛查的梯队（可加 tier3）
--max-stocks10龙头池上限（限频保护）
-p/--profileaggressive_shortcalc_indicators 配置档
--min-pass2进入后续阶段的最少通过维度数（1/2/3）
--with-yanbaooff对通过标的拉研报（慢）
--with-sell-initoff打印 sell_monitor 登记命令
--reportoff为通过标的生成 PNG 报告
--no-update-mappingoff不写回 stock_mapping.json
--rescan-bankuaioff强制重扫板块（忽略当天 JSON）
--bankuai-json空直接用指定 JSON（跳过扫描，最快）
--dry-runoff只输出龙头池不筛查

用法示例

# 默认：概念板块 Top3，tier1+tier2，aggressive_short，至少 2 维通过
uv run python scripts/run_leader_pipeline.py

# 行业板块 + 超短线 + 生成 PNG
uv run python scripts/run_leader_pipeline.py --plate-type 行业 -p ultra_short --report

# 指定板块 + 三梯队 + 研报 + sell_monitor 登记命令
uv run python scripts/run_leader_pipeline.py --sectors 电力 --tiers tier1,tier2,tier3 \
    --with-yanbao --with-sell-init

# 预览龙头池（不触网不筛查）
uv run python scripts/run_leader_pipeline.py --dry-run

# 复用已有 bankuai JSON（跳过 zzshare 扫描）
uv run python scripts/run_leader_pipeline.py --bankuai-json data/reports/bankuai/bankuai_2026-08-26_行业.json

scripts/run_all.py 完成总结

重写了 scripts/run_all.py，从「固定 4 任务硬编码」改为场景驱动 + 注册表的批量编排器。

顺带修了原文件的 2 个 bug

  • 原 PIPELINE 引用 services/fetch_klines/main.py ——该服务不存在，跑必崩
  • 原 calc_indicators 调用没传 symbol ——而它是必填位置参数，会报错退出

5 个场景预设（--scenario）

场景 顺序执行的服务 用途
daily（默认）alarming → bankuai → news → holdings → report日常盘后
macromacro_data → macro_charts宏观复盘
stock（需 --symbol）calc → yanbao → sell → report单标的复盘
pipelinerun_leader_pipeline龙头批量筛查
fullmacro + daily + pipeline（+ stock 若给 symbol）完整复盘

参数控制（覆盖不同复盘场景）

参数 默认 作用
-s/--scenariodaily选预设场景
--date昨天参考日
--symbol空个股代码（stock 必填，full 给了更全）
-p/--profileaggressive_short配置档，透传 calc/alarming/sell/pipeline
--plate-type概念板块类型，透传 bankuai/pipeline
--reportoffcalc 加 -r 生成 PNG
--include a,b,c空场景基础上追加服务
--exclude a,b,c空场景中移除服务
--skip-slowoff跳过触网重服务（无网/赶时间）
--timeout N600单任务超时秒数
--dry-runoff只打印命令不执行
--list-servicesoff列出所有服务+场景后退出

用法示例

uv run scripts/run_all.py                              # 日常盘后
uv run scripts/run_all.py -s macro                      # 宏观复盘
uv run scripts/run_all.py -s stock --symbol 600550      # 个股复盘
uv run scripts/run_all.py -s full --symbol 600550       # 完整复盘
uv run scripts/run_all.py --skip-slow                    # 跳过慢服务
uv run scripts/run_all.py --include yanbao --exclude news  # 自定义增删
uv run scripts/run_all.py --dry-run -v                   # 预览命令
uv run scripts/run_all.py --list-services                # 查服务清单

设计要点

  • 服务注册表（SERVICES 字典）：每个服务声明 cmd/scenarios/slow/needs_symbol，加新服务只改一处
  • 场景解析（_resolve_services）：scenario 基底 → include 追加 → exclude 移除 → skip-slow 过滤 → 无 symbol 时自动剔除 needs_symbol 服务
  • 执行隔离：单任务超时（--timeout）+ 全流程硬上限 1800s，失败不阻断后续，末尾打印 ✓/✗ 汇总

dry-run 全场景验证通过：daily(5)、macro(2)、stock(4)、full+symbol(11)、skip-slow(2)、include/exclude 增删、stock 缺 symbol 报错均符合预期。
