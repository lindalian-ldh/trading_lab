## 二、本轮实测：数据底座（决定架构的 8 个事实）

> 这一节是整个方案的地基。**禁用东财之后**，能用的两条腿是 **zzshare** 和 **腾讯源**（`ak.stock_zh_index_daily_tx` / `ak.stock_zh_a_hist_tx`）。以下全部实测通过。

### 事实 1（最关键）：龙虎榜的 `concepts` 与"题材"板块是**同一套编码**，可直接 join

`zzshare.lhb_list(date1)` 每条记录带 `concepts` 字段：

```
"concepts": "801007:房地产,801678:物业服务,...,801159:机器人概念,..."
```

而 `zzshare.plates_list(plate_type=17)`（题材）用的正是 **801xxx** 编码：

| 题材 | 编码 | 成分股数 |
|---|---|---|
| **半导体设备** | **801490** | **6** |
| 第三代半导体 | 801068 | 49 |
| 光刻胶 / 光刻机 | 801222 / 801476 | — |
| 智能电网 | 801346 | **500** |
| 黄金 | 801048 | 89 |
| 军工 / 军工电子 | 801062 / 801491 | — |

**实测 join 覆盖率：单日样本 852 个编码命中 746 个 = 87.6%；全量回填（431,537 行 / 822 编码）为 86.4% 的行覆盖。**

⇒ **需求 #1 不需要自建"股票→板块"映射表，也不需要名称模糊匹配 —— 按代码直连即可。**
剩余 13.6% 的编码不在 `plates_list(17)` 内且取不到成分股 ⇒ **只能给上榜家数、不能给上榜率**
（详见下方 [P0.3 完成记录 → 发现 D](#p03-完成记录2026-10-03)）。

> **⚠️ 金额字段的坑（P0.3 实测发现，务必先读）**：`lhb_list` 里的 `buy_in` 是**净额**，
> 而 `buy_group_icons` / `sell_group_icons` **只是"有标记的席位"**（机构/知名游资/深股通），
> **不是全部席位** —— 万科A 的 icon 买入额合计 3.9 亿，真实毛额是 6.9 亿。
> ⇒ **"买卖比"必须走 Tier 2 `lhb_detail`（`buy_total`/`sell_total`），1 次/股。**
> 详见下方 [P0.3 完成记录 → 三个字段语义发现](#p03-完成记录2026-10-03)。

### 事实 2：`plates_rank_days` / `plates_rank_days_new` **不可用**（返回 None）

SDK 里存在这两个方法（区间累加排名 / 带 `is_new` 新进标记），但**实测一律返回 None**（疑似更高订阅档）。
⇒ **"持续性"必须自己从日频数据算**，不能指望接口直接给。这是 Phase 1 的一个必做计算项。

### 事实 3：`plates_trend` 支持概念（885xxx）但**不支持题材（801xxx）**

| 调用 | 结果 |
|---|---|
| `plates_trend(plate_type=15, plate_code='885955', 2024Q1)` | ✅ **58 条**（含 rate/score） |
| `plates_trend(plate_type=15, plate_code='885955', 2022Q1)` | ✅ 53 条 |
| `plates_trend(plate_type=15, ..., 2019Q1)` | ❌ 0 条 |
| `plates_trend(plate_type=17, plate_code='801490', ...)` | ❌ **0 条** |

⇒ 概念板块日线可回溯到 **约 2022 年（~4.5 年）**；题材板块**没有现成日线**。

### 事实 4：`plates_stocks(17)` 给成分股，且带 `time_in`（可做近似 point-in-time）

```
{"plate_code":"801490","plate_name":"半导体设备","stock_code":"002371",
 "stock_name":"北方华创","time_in":"2021-07-14","time_out":""}
```

`time_in` 有值、`time_out` 全部为空。

⇒ **能按 `time_in` 还原"某日该股是否已在该板块"**，比纯当前快照好得多；
但**已退出的成分股不会出现在列表里** ⇒ **仍有残余幸存者偏差，必须在文档里写明**（对"印象面板"可接受）。

### 事实 5：**板块成分股数量差异极大 —— 频率指标必须归一化**

半导体设备 **6** 只 / 第三代半导体 49 只 / 黄金 89 只 / **智能电网 500 只**。

⇒ 同一句"今天有 3 只上榜"：对 6 只的板块是**半个板块**，对 500 只的板块**等于噪声**。
**所以"上榜频率"必须除以板块规模**（或用该板块历史均值做基准）。
**这就是"集中度"缺的那个分母 —— 现在有了，不再是不可证伪的词。**

### 事实 6（重要）：腾讯个股历史很长 ⇒ **可以自己合成主题指数**

| 标的 | 腾讯源实测 |
|---|---|
| `sz002371` 北方华创 | **3939 根**（2010-03 起） |
| `sh600547` 山东黄金 | **5370 根**（2003-08 起） |
| `sz300567` 精测电子 | 2391 根（2016-11 起） |
| `sh512480` 半导体 ETF | 1774 根（2019-06 起） |
| `sh000001` 上证综指 | 8726 根（约 35 年） |

⇒ **用成分股（`plates_stocks`）+ 腾讯个股日线合成主题指数，可拿到 10~20 年历史。**
这一条同时解决三个旧问题：
1. [`交接总结.md`](交接总结.md) 记录的"baostock 无 ETF 历史，只有 181 根"；
2. **新 ETF 历史太短**（实测：561380 电网设备仅 **431 根**、588170 科创半导体仅 **363 根**）→ 无法单独验证；
3. **"科创50 无法双体制校验"**（基日 2019-12-31）→ 合成指数可覆盖 2016-2020。

**这是需求 #2 从"不可验证"变成"可验证"的唯一原因。**

### 事实 7：龙虎榜历史深度 = **2025-01-02 起（约 430 个交易日）**

禁用东财后，龙虎榜**只剩 zzshare 一个源**，实测边界：

| 日期 | 返回条数 |
|---|---|
| 2024-12-16 / 12-30 / 12-31 | **0** |
| **2025-01-02** | **80** |
| 2025-01-03 / 01-06 | 73 / 74 |
| 2026-09-30 | 66 |

⇒ 龙虎榜只有 **~1.75 年**。
**这对需求 #1 是可接受的** —— 因为需求 #1 的定位是**主观印象（描述性）**，不是统计验证。
但必须写明：**龙虎榜层目前不能宣称任何预测力**；面板应从今天开始**累积**，将来才谈验证。

### 事实 8：`plates_rank` 与 `plates_stocks` 可用（补充原料）

- `plates_rank(plate_type=17, date1, limit)` ✅ → 当日题材热度：`rate` / `trade_money` / `volume_ration` / `score` / `money_leader_buy` / `money_leader_sell`
- `plates_stocks(plate_type=17, plate_code)` ✅ → 成分股（含 `time_in`）
- `sentiment_timing(date1)` ✅ 返回 `{"market_timing": -1, "timing_signal_type": 0}` —— 第三方现成择时信号，**语义与验证状态未知，仅作参考，不进逻辑**
- `lhb_detail` ❌ 返回 None（需单股参数且不稳定）

### P0.3 收尾：空结果护栏 + 每日挂载 + Tier 2 策略（2026-10-03）

#### ① 空结果护栏（修掉一个静默数据洞）

**问题**：原 `update()` **无条件**把抓取结果写进 state（含空结果）。而厂商日批**约 18:00 才落库**
（证据：`plates_rank` 的 `time` 字段 = `2026-09-30 18:01:03`），现有 cron 却是 **16:30**
⇒ 当天数据还没发布 ⇒ 脚本会把**一个真实交易日记成 0 并永久跳过**（以后重跑也不修）。

**修法**：新增 `_is_publish_risky(d)` —— 交易日返回空、且**该日期还没过去一天** ⇒
判为「尚未发布」，**不写 state**，留给下次重试；新增 `days_pending` 统计。

**可见性**：`status()` 新增 `zero_days`（记成 0 的交易日），CLI 打「静默空洞检查」行。
这是 cron 静默失败**唯一的可见线索**（全期日均 71.8 只、最少 46 只 ⇒ 交易日为 0 几乎不可能是真的）。

#### ② 另一个真 bug：Tier 2 的待处理判据错了

**问题**：原 `todo` 依据 `state['list']` ⇒ 对**已回填 Tier 1 的日期整体跳过** ⇒
`--tier 2` **永远补不上任何东西**（补最近 60 天会什么都不做）。

**修法**：Tier 2 的 `todo` 依据 **`state['detail']`**；若某天 Tier 1 也缺，
在同一次循环里先补 Tier 1。已回填的日期**直接读库、不重复联网**。

**性能**：原 `_upsert_stock_detail` 每股重写整个 parquet（4320 次读写）；
改为 `_upsert_stock_details_bulk` **按天一次读写**。实测 Tier 2 ≈ 0.94 秒/股。

#### ③ 每日挂载：方案 A（**不改 crontab**）

在 [`run_all.py`](run_all.py) 的 `SERVICES` 加 `lhb`，并放进 `daily` / `full` 场景**最前面**
（它是**数据获取**步骤，且将来的板块轮动面板要读它的新数据）：

```bash
uv run python scripts/lhb_update.py --tier 2 --recent 90 --end <昨天> --throttle 0.8
```

三个关键点：
- **不带 `--start`** ⇒ Tier 1 从 2025-01-02 起扫描，**只补缺失的日子** ⇒ 自愈任何漏跑；
- **`--end 昨天`** ⇒ 绝不碰"当天尚未发布"的数据（配合护栏双保险）；
- **`--recent 90`** ⇒ 见下。

#### ④ 为什么 Tier 2 必须有滚动窗口（`--recent 90`）

Tier 1 是 **424 天全量**回填的，而 Tier 2 只回填最近一段。
若每日任务不带窗口，它会看到 **历史 300+ 天永远没有 detail**，
于是**每天都去补这 300+ 天**（约 2 万次调用、数小时）—— 每日任务直接废掉。

⇒ `--recent 90` 把 Tier 2 限制在最近 90 个交易日内；
**而 Tier 1 仍扫全区间**，以保留自愈能力（有单测专门锁死这个不对称）。

#### ⑤ Tier 2 落地方式：两者都做

| 步骤 | 做法 | 成本（实测） |
|---|---|---|
| **先补最近 60 个交易日**（2026-07-08 ~ 2026-09-30） | 后台一次性补 | 约 4300 次调用，**≈64 分钟**（0.94s/股） |
| **再挂每日增量** | 由 run_all 的 `lhb` 步骤带 `--tier 2 --recent 90` | 每天约 72 次调用，**≈1 分钟** |

⇒ **买卖比 / 碾压占比从 2026-07-08 起可用**；更早的日期仍是 `n/a`（面板按设计显示 `n/a`，不编数）。

#### ⑥ ⚠️ 发现 F：买卖比的**基线就是 0.50** —— 不能把"水平值"当信号

**全量 60 天（2026-07-08 ~ 2026-09-30，4092 个股日）实测：**

| 主题 | 上榜股日 | 聚合买卖比 | 碾压占比(≥0.65) |
|---|---|---|---|
| 半导体设备 | 109 | **0.511** | 14.7% |
| 第三代半导体 | 155 | **0.510** | 13.5% |
| 智能电网 | 321 | **0.517** | 15.3% |
| 黄金 | 83 | **0.517** | 8.4% |
| 芯片 | 1024 | **0.512** | 15.2% |

**全市场分布**：均值 **0.520** / 中位 **0.508** / 横截面 std **0.127**（范围 0.095 ~ 1.000）；
比值 ≥0.65 占 **15.4%**、≤0.35 占 **7.7%**。

**为什么会这样（机制）**：龙虎榜的上榜门槛是**买卖双方都要足够大**才产生大额席位 ——
所以活跃股的毛额买卖额**天然接近对称**。**0.50 是结构性基线，不是"资金平衡"的信号。**

**但动态范围是可用的 —— 关键在下面这个对比：**

| 量 | std |
|---|---|
| 个股买卖比的**横截面** std | **0.127** |
| **全市场日均值**的**时间序列** std | **0.0226** |

⇒ 聚合已经把噪声压掉了（0.127 → 0.023，约 1/5.6）。
**所以"主题聚合比值偏离当日全市场基线"是有信息的量，而"聚合比值本身"不是。**

**⇒ 面板的正确用法（替代原设计）：**

| ❌ 不要 | ✅ 要 |
|---|---|
| 直接显示"买卖比 0.512"，暗示它有含义 | 显示 **该题材当日聚合比值 − 当日全市场聚合比值**（去掉共同成分） |
| 用 0.5 附近的绝对差异跨主题比较 | 用 **碾压占比**（8%~15% 有真实区分度） |
| 把"≥0.65"当作罕见强信号 | 记住它占比 15.4%，**不罕见**；罕见的是"某个题材里集中出现" |
| 需要 60 天历史才能算分位 | 去均值法**第 1 天就能用**（同日横截面基线），分位作为第二层 |

**这条发现的价值在于：它拦下了一个本来会直接写进面板的假信号。**
这正是 [`交接总结.md`](交接总结.md) 反复强调的那类坑 —— "我以为是"要先被数据检验。

效应口径沿用 [`audit_regime_hold.py`](audit_regime_hold.py)：
**次日开盘入场 → 第 H 根收盘出场**，效应 = 信号日均值 **− 非信号日均值**（pp）；
显著性用片段匹配重采样 placebo（保持片段长度分布，单尾）。

#### ① L1 结构破坏 —— **方向冻结为「看涨反转」**（下跌结构被破坏 ⇒ 调升仓位中枢）

| 子项 | 冻结定义 |
|---|---|
| 摆动点（分型） | 窗口 **k=5**：第 i 根是摆动低点 ⟺ `low_i` 严格小于 `[i-5, i+5]` 内其余 10 根的 `low`；摆动高点同理取最大。⇒ 摆动点在**第 i+5 根收盘时**才被确认 |
| "不再创新低" | `close_t > min(close_{t-20} … close_{t-1})`（**严格大于**前 20 日最低**收盘**；不含当日） |
| "突破前一反弹高点" | `close_t > H_last`；`H_last` = 截至 t 日**已确认**的最近一个摆动高点的 `high`；不存在则不触发 |
| 确认（1 根 K 线） | 次日 `close_{t+1} > H_last`（**仍站上**）才算确认；**信号日 = t+1**，入场 = **t+2 开盘** |
| 方向 | **看涨**（右侧转多）。本条是冻结项：**禁止**实现成"结构破坏 ⇒ 看跌减仓" |

#### ② L2 均线转向

| 子项 | 冻结定义 |
|---|---|
| 均线周期 | **MA10 / MA30**（简单移动平均，收盘价） |
| 上穿 | `MA10_{t-1} ≤ MA30_{t-1}` **且** `MA10_t > MA30_t` |
| MA30 斜率 | 对 `MA30` 在 `[t-4, t]` 共 **5** 个点做 OLS（x = 0…4），要求**斜率 ≥ 0** |
| 信号日 / 入场 | 信号日 = t；入场 = **t+1 开盘** |

#### ③ RS 相对强度（**必须与绝对价格绑定** —— 见第五章坑 3）

| 子项 | 冻结定义 |
|---|---|
| 比价 | `R_t = close_theme_t / close_anchor_t` |
| 走强 | `R_t > R_{t-20}`（窗口 **20** 日） |
| 绝对价格绑定 | **且** `close_theme_t > MA20_theme_t` |
| 信号日 / 入场 | 信号日 = t；入场 = **t+1 开盘** |

#### ④ 层组合语义：**同日 AND**（不是"N 日内共现"）

- `L1`；`L1+L2` = `L1(s) ∧ L2(s)`；`L1+L2+RS` = `L1(s) ∧ L2(s) ∧ RS(s)` ——
  **必须是同一个交易日 s**（与草案原文"三层**同时**满足"一致）。
- ⇒ 若联合频次 < 2 次/年，按 kill criterion 3 **退化为"只观察"**；
  **不允许**事后改成"N 日内先后出现"来救频次（那属于修改冻结项）。

#### ⑤ 持有期与主判据

- 报告全部 **H ∈ {5, 10, 20, 40}**；
- **主判据 H = 20**（与 PANIC_DOWN 的 20 日持有窗口可比）；
  H ∈ {5, 10, 40} **只作描述性稳健性列，不参与通过/不通过**。

#### ⑥ 验收判据（全过 + 频次）

1. `\|t\| ≥ 1.96`；
2. `\|效应\| ≥ MDE`，其中 **MDE = 2.80 × SE**（α=0.05 双尾 + 80% 功效），
   且 **SE 必须按交易日聚类**（同一交易日的多个标的不算独立样本）—— 与
   [`paired_stats.min_detectable_effect`](../services/calc_indicators/paired_stats.py) 口径一致；
3. **两段同号**：A 段 **2016-01-01 ~ 2020-12-31**、B 段 **2021-01-01 ~ 2023-12-31**
   （**B 段不含 2024 年之后**）；
4. placebo（片段匹配重采样，保持片段长度分布，单尾）`p < 0.05`；
5. **联合频次 ≥ 3 次/年**（否则无实用价值）。

**科创系例外**（`sh000688` 自 2020-01-02，A 段在数学上不存在）：
科创半导体 / 科创创业50 **放弃"两段同号"**，主判据 = 全区间（2020-2026）+ placebo + 频次，
结论必须标注**"该主题无第二体制证据"**。

#### ⑦ OOS 锁定段

**2024-01-01 ~ 2026-09-30，只看一次。**
前提是 ⑥-3 的 B 段已收窄到 2023-12-31 —— 否则 OOS 落在 B 段内、已被"看过"，不是样本外。

#### P0.5-A · 面板口径冻结（需求 #1 专用；**开始累积面板输出前必须写死**）

面板虽然"只显示不决策"，但它的数字会**逐日累积**。若中途改口径，
累积序列就前后不一致（无法回看、无法日后验证）。因此**在写代码之前先冻住**：

**范围**：主题宇宙 = [`core/theme_universe.THEMES`](../core/theme_universe.py)（10 个主题）；
数据源 = [`core/lhb_store`](../core/lhb_store.py) 的 LHB 累积 + `plates_rank(17)`；日期 = 交易日。

**逐 (交易日, 主题) 的定义**：

| # | 指标 | 冻结定义 |
|---|---|---|
| ① | `n_listed` | 当日该主题**题材集合内**出现在龙虎榜的**去重个股数**（去重键 `(date, stock_code)`） |
| ② | `n_constituents` | 该主题成分股**并集去重**数（来自 P0.2 的当前快照） |
| ③ | `listed_rate` | `n_listed / n_constituents`；`n_constituents = 0` ⇒ **`n/a`** |
| ④ | `rate_pct_rank` | `listed_rate` 在该主题**过去 N=120 个交易日**（含当日）分布中的百分位；**有效样本 < 60 ⇒ `n/a`** |
| ⑤ | `roll3` / `roll5` | 过去 3 / 5 个交易日 `n_listed` 之和（含当日） |
| ⑥ | `streak` | 截至当日、`n_listed ≥ 1` 的**连续**交易日数 |
| ⑦ | `buy_sell_ratio` | `Σ buy_total / (Σ buy_total + Σ sell_total)`，**仅用 Tier2 覆盖到的个股**；当日 Tier2 未覆盖 ⇒ **`n/a`** |
| ⑧ | `crush_share` | 当日该主题内个股 `buy_sell_ratio ≥ 0.65` 的**占比**（仅 Tier2 覆盖个股） |
| ⑨ | **`ratio_excess`** | `buy_sell_ratio(主题) − buy_sell_ratio(当日全市场)` ← **发现 F 的修正**：0.50 是结构性基线，只有偏离才有信息 |
| ⑩ | 全市场参照 | `buy_sell_ratio(当日全市场)` = 当日**全部** Tier2 个股的 `Σbuy/(Σbuy+Σsell)` |

**状态标签（优先级从高到低，只取第一个命中）**：

| 标签 | 条件 |
|---|---|
| `🆕 新进` | 当日 `n_listed ≥ 1` 且**前 3 日**均 `n_listed = 0` |
| `🔥 共识增强` | `roll5` **连续 2 日严格递增**（`roll5(d) > roll5(d-1) > roll5(d-2)`） |
| `💤 冷却` | `rate_pct_rank ≤ 0.20`（样本足时）；或 `roll5` **连续 2 日下降** |
| `➖ 持平` | 其余 |

**显示规则（硬约束）**：
- 主体**只有 5~10 行**（主题），一屏内看完；**不做全市场板块涨幅榜**（那是 App 的强项）
- 任何缺失一律打印 **`n/a`** —— **绝不填 0、绝不估算、绝不用近似替代**
  （典型：Tier2 未覆盖 ⇒ `买卖比` 与 `碾压占比` 显示 `n/a`；
   不在 `plates_list(17)` 内的题材 ⇒ `listed_rate` 显示 `n/a`，只给 `n_listed`）
- 必须打印**「数据充分度」段**（累积天数、Tier2 覆盖天数、有效样本是否达 60 日门槛）
- 结尾必须打印 **`⚠️ 本板只做确认与证伪，不产生买入信号，不占仓位权重`**

**冻结规则**：以上 ①~⑩ 与状态标签逻辑、参数（N=120、最小样本=60、滚动 3/5 日、
碾压阈值 0.65、状态优先级）**一旦开始累积面板输出即不得修改**。
如确需修改，必须**新开版本号（v2）并重算全部历史**，不许在同一序列上悄悄改口径。

### Phase 0 的 kill criteria

- **P0.4 若合成主题指数与 ETF 相关性 < 0.8 → 该主题不采用合成指数**，降级为"只显示、不验证"（不允许用错误的价格序列去验证信号）。
- **P0.2 若某主题的题材过宽（如 500 只）且无法收窄 → 该主题的"上榜频率"标注为不可用**，只用成分股数加权或改用更窄的题材。
- **P0.1 若腾讯源取不到某标的 → 明确标注数据缺失**，绝不用东财兜底。

2. **`上榜率` 是唯一崭新的数字** —— 归一化后才可跨板块比较（半导体设备 3/6=50% 与智能电网 9/500=1.8%）。**同花顺的龙虎榜是个股维度，没有这个跨板块的归一化视图。**
3. **`5日趋势` sparkline（▁▂▃▄▅▆▇█）** —— 把"持续性 vs 单日爆发"做成**一眼可见的形状**。这是本板最贴近你原始需求（"看连续几天的资金行为"）的一列。
4. **`数据充分度` 必须显式打印** —— 沿用本仓库的硬门槛哲学（[`analyze_signal_ledger.py`](scripts/analyze_signal_ledger.py) 在 <10 个交易日时**硬性拒绝给结论**）。分位数需要 ≥60 日历史；**样本不足时打印 `n/a` 而不是编一个数**。

  且红利/银行的 `|t| ≈ 2.6`。经济上讲得通（防御板块均值回归、突破多为衰竭）。

- **发现 J（方法学局限，记下来留给下一个预注册）**：预注册的 placebo 是

  而"调仓位中枢"这个用途里，**负效应和正效应同样可执行**（负 ⇒ 减仓）。
  ⇒ 下一个预注册应把 placebo 改成**双尾**（或对称地同时报两侧）。
  **但本轮不许改**（看到数据后改判据就是移动球门）。
