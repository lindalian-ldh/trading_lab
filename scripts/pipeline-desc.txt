实现说明
创建 scripts/run_leader_pipeline.py，把原本需手动串接的链路自动化：

bankuai 扫龙头 → calc_indicators 批量筛查 → 按通过维度过滤 → yanbao/sell_monitor 衔接 → 龙头池沉淀回 stock_mapping.json

设计取舍
bankuai / yanbao-info / PNG 报告：用 subprocess 调 CLI（要拉 zzshare/PDF，重，且 CLI 自带 token/env 处理）
calc_indicators 筛查：同样用 subprocess + 正则解析稳定输出（一开始试过 in-process 调 _evaluate_stock，但 calc_indicators 的 config.py 与项目根 config/ 包命名冲突被 core.logger 提前缓存遮蔽；subprocess 方案与 run_all.py 风格一致，且不被内部 API 变更影响）
sell_monitor：只打印登记命令不自动登记——系统是纯信号，进场需人确认 entry-price
参数速查
参数	默认	控制场景
--date	昨天	参考日期
--plate-type	概念	板块类型 概念/题材/行业
--sectors	空	指定板块名（逗号分隔），非空仅扫这些
--top-n-sectors	3	热门板块取前 N 作为龙头池来源
--tiers	tier1,tier2	参与筛查的梯队（可加 tier3）
--max-stocks	10	龙头池上限（限频保护）
-p/--profile	aggressive_short	calc_indicators 配置档
--min-pass	2	进入后续阶段的最少通过维度数（1/2/3）
--with-yanbao	off	对通过标的拉研报（慢）
--with-sell-init	off	打印 sell_monitor 登记命令
--report	off	为通过标的生成 PNG 报告
--no-update-mapping	off	不写回 stock_mapping.json
--rescan-bankuai	off	强制重扫板块（忽略当天 JSON）
--bankuai-json	空	直接用指定 JSON（跳过扫描，最快）
--dry-run	off	只输出龙头池不筛查

重写了 scripts/run_all.py，从「固定 4 任务硬编码」改为场景驱动 + 注册表的批量编排器。

5 个场景预设（--scenario）
场景	顺序执行的服务	用途
daily（默认）	alarming → bankuai → news → holdings → report	日常盘后
macro	macro_data → macro_charts	宏观复盘
stock（需 --symbol）	calc → yanbao → sell → report	单标的复盘
pipeline	run_leader_pipeline	龙头批量筛查
full	macro + daily + pipeline（+ stock 若给 symbol）	完整复盘
参数控制（覆盖不同复盘场景）
参数	默认	作用
-s/--scenario	daily	选预设场景
--date	昨天	参考日
--symbol	空	个股代码（stock 必填，full 给了更全）
-p/--profile	aggressive_short	配置档，透传 calc/alarming/sell/pipeline
--plate-type	概念	板块类型，透传 bankuai/pipeline
--report	off	calc 加 -r 生成 PNG
--include a,b,c	空	场景基础上追加服务
--exclude a,b,c	空	场景中移除服务
--skip-slow	off	跳过触网重服务（无网/赶时间）
--timeout N	600	单任务超时秒数
--dry-run	off	只打印命令不执行
--list-services	off	列出所有服务+场景后退出
