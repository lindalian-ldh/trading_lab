## 一次性准备

```bash
# 1. 依赖
uv sync

# 2. 生成观察清单（三段结构，见下）
uv run python scripts/build_watchlist.py --target 50 --dry-run   # 先预览
uv run python scripts/build_watchlist.py --target 50             # 正式生成
```

### 观察清单是**三段结构**，缺一不可

| 段 | 来源 | 作用 |
|---|---|---|
| ① **持仓** | 资金流水（`剩余数量 > 0`） | 必须盯 |
| ② **近期成交** | 资金流水（按成交笔数） | 保持连续性 |
| ③ **候选宇宙** ← **关键** | **bankuai 热门板块人气股** | **唯一真正的对照组** |
| ④ 手工保留 | 原清单中未被 ①②③ 覆盖的 | 不静默丢弃你加的票 |

**为什么第③段必须来自外部、不能从成交记录生成**：

分析器要回答「**我的判断加了多少分**」，靠的是「**被标记但你没买**」那批当对照。
若清单只由成交记录生成，则清单上每只都是你买过的——"没买"只代表"某天没买"，
**对照组系统性失效**。（第一版清单就踩了这个坑：20 只全部来自成交记录，真对照 = 0。）

**⚠️ 一个诚实的局限**：第③段来自涨停/人气股，与你实际做的 ETF 主题**风格不同**。
所以它是"**市场在关注什么**"的对照，不是"**我会考虑什么**"的对照。
要更贴近后者，就在生成后手工加入你的自选（生成器会保留，归入 ④）。

**其他要求**：
- **至少 15 只**，建议 30~50（同日对照需要足够的票）
- 可以含 ETF（SURVIVABILITY 的价格否决已对 ETF 豁免；双因子排名会自动排除 ETF）
- **实测成本**：50 只跑打分 CLI 约 **29s**，记录台账约 **33s**（缓存命中时）

## 每日流程（收盘后，约 3 分钟）

### Step 1 · 市场状态 + 风险预警 → 决定仓位

```bash
# 1a. 市场状态（唯一经检验有效的择时信号源）
uv run python services/calc_indicators/main.py 600000 --no-weekly
#     看输出末尾的【维度E - 市场状态雷达】
#     --no-weekly 只跳过周线(D)，保留市场状态(E)

# 1b. 系统性风险预警（7 信号，≥4 红灯 → 降仓）
uv run services/alarming_monitor/main.py
```

| 看到 | 做什么 |
|---|---|
| 状态 = **PANIC_DOWN** | 加仓宽基 ETF，持有约 **20 个交易日**后减回 |
| 其他 6 种状态 | **不加仓**（不要因为 A/B/C 亮灯就买） |
| **⛔「今日择时判断不可用」** | **当天不做任何仓位决策**（见下） |
| alarming ≥4 红灯 | 降仓 |

### ⛔ 关于「今日择时判断不可用」

取数失败时，`main.py` 会打印醒目横幅，并**同时写一行到 stderr**：

```
  ╔════════════════════════════════════════════════════════════════╗
  ║  ⛔ 今日「择时判断」不可用 —— 请勿据此做任何仓位决策            ║
  ╚════════════════════════════════════════════════════════════════╝
[regime-unavailable] 市场状态不可用：指数 sh000001 数据获取失败 —— 今日勿做择时决策
```

**关键：此时择时信号是「未知」，不是「非恐慌」。** 把未知当成安全是这里最容易犯的错。

- 处理：① 稍后重跑 Step 1a ② 检查网络 / baostock
- **退出码仍是 0**（维度E 的契约是"只读、不参与 A/B/C 判定"；改退出码会让
  `scan_leaders_chart.sh` 把正常筛查判为失败）
- 记台账时若 regime 列为空，脚本会在末尾再警告一次：
  `⛔ 注意：本次 regime 列全部为空` —— **这些行不能当作有效的择时观测**

> 想看这条警告长什么样？用无效指数触发：
> `uv run python services/calc_indicators/main.py 600000 --no-weekly --index sh999999`

> 择时的诚实预期：2021-2026 约 +4.15pp/20日（p=0.000）；但 **2016-2020 为 +0.48pp（不显著）**。
> 每年约 3 次机会，单次最差 −16.5%，28% 的次数是亏的。

### Step 1 附 · 双因子原料（**自动显示，无需额外命令**）

Step 1a 的输出里，**维度E 之后**会自动多出一块（同一个命令，不用再跑别的）：

```
【双因子原料（只显示，不参与任何判定）】
  个股 ATR%:    1.75%   [低波<2.69]
  距MA20%:     +3.05%   [贴近/上方>-1.81]
  判读卡格位: 低波 × 贴近/上方  →  实测 -0.237pp/10日 (t=-2.94, n=3571)  ⛔ 有强负证据
  判读顺序: 先看 ATR —— 低波那一整行实测全为负（-1.350 / -0.341 / -0.237，|t| 均 >2.9），ATR 低时无论多超跌都不该买
  ⚠️ 判读卡仅在「系统已触发」时适用；当前未触发 → 上表仅供参考
  ⚠️ 样本内实测、幅度微小（最好格 +0.917pp vs 单笔噪声 8.72pp），不可单独作为决策依据
```

### ⛔ 卡适用的**三个前提**（缺一个就不能用）

| # | 前提 | 不满足时的表现 |
|---|---|---|
| 1 | **必须是个股** | 输出会显示「本标的是 ETF，判读卡不适用」 |
| 2 | **必须已触发 signal 池**（A或B通过 且 C通过 且 门控放行） | 输出会显示「当前未触发 → 上表仅供参考」 |
| 3 | 幅度上它只够做"否决"，不够做"买入" | 见下方「正当用法是"否决"」 |

**前提 1 的原因**：判读卡在 300 只**个股**上测得（universe 只含 600/601/603/605/000/001/002/003/300/301/688/689 段，**样本内 0 只 ETF**）。
ETF 的净值、波动、偏离分布与个股不同，套用个股的分位没有依据。
（你的自选 20 只里有 8 只是 ETF —— 对这些只有前两行数值可看，格位不适用。）

**前提 2 的原因**：同一因子在 signal 池外**方向会翻转**（ATR% 全样本 Q1 +0.119 → Q5 −0.391，
与池内 Q1 −0.531 → Q5 +0.678 相反）。所以"未触发"时的格位数字是从别的条件下测出来的，不适用于当前状态。

### ⚠️ 第 4 个前提：格位可能"差一点就翻脸"

3×3 是**硬分档**，边界附近必然有"动一点就换格"的问题。例（实测 603773 沃格光电）：

```
距MA20% = -1.71%   →  高波 × 贴近/上方  = -0.426pp（证据不足）
距MA20% = -1.85%   →  高波 × 中间      = +0.695pp（有强证据）
        ↑ 只差 0.14pp，结论反转 1.12pp
```

**股价动 0.1% 就能改变结论** —— 这种数字不能当确定判读用。

所以 `main.py` 现在会在格位距分界 ≤ 档宽 10% 时**自动打出警告**：

```
  ⚠️ 格位不稳：距MA20% -1.71 距分界 -1.81 仅 0.10pp（档宽 3%）
     邻格「高波 × 中间」= +0.695pp (t=+3.49) —— 结论会反转 1.12pp
     价格再动约 0.10% 就会翻格；**不要把本行当作确定判读**
```

**看到这行时，请把该格位视为"不可用"**，而不是"参考一下"。

**⚠️ 这里最容易犯的错：只看"距MA20 很负 → 超跌 → 可以试仓"。**

实测证明这个推断会把你送进**最差的一格**：

| 只看距MA20 | n | 同日超额 | t |
|---|---|---|---|
| 超跌（< −5.31%） | 7,293 | **+0.244pp** | +2.53 ✅ 看起来成立 |

| 把"超跌"按 ATR 拆开 | n | 同日超额 | t |
|---|---|---|---|
| 超跌 + **低波** | 1,023 | **−1.350pp** | **−5.88** |
| 超跌 + 中波 | 2,382 | −0.169pp | −1.22 |
| 超跌 + **高波** | 3,888 | **+0.917pp** | **+6.24** |

**那个 +0.244pp 全部来自"高波"子集。低波子集是强烈负的。** "距MA20 很负"本身不告诉你任何事——它可能是"急跌将反弹"（好），也可能是"阴跌没底"（最差）。**区分它们的是 ATR。**

## 人工判读卡

**只适用于 signal 池**（A或B通过 且 C通过 且 门控放行）。

分档边界（signal 池三分位）：
- ATR%：低波 **< 2.69%** ｜ 中波 2.69~3.91% ｜ 高波 **> 3.91%**
- 距MA20%：超跌 **< −5.31%** ｜ 中间 −5.31~−1.81% ｜ 贴近/上方 **> −1.81%**

| | 超跌 | 中间 | 贴近/上方 |
|---|---|---|---|
| **低波** | **−1.350** (t=−5.88) | −0.341 (t=−3.47) | −0.237 (t=−2.94) |
| 中波 | −0.169 (t=−1.22) | −0.228 (t=−1.99) | +0.081 (t=+0.54) |
| **高波** | **+0.917** (t=+6.24) | **+0.695** (t=+3.49) | −0.426 (t=−1.67) |

（格子内 = 同日超额 pp / 10日、次日开盘入场；括号内为 t 值）

### 判读顺序：**第一步先看 ATR，不是看距MA20**

**第一步 · ATR%**

| ATR% | 结论 |
|---|---|
| **< 2.69%（低波）** | **整行都是负的，不要买** —— 不管多超跌（|t| 全部 > 2.9） |
| 2.69~3.91%（中波） | 三格都不显著，**没有证据** |
| **> 3.91%（高波）** | 再看距MA20 |

**第二步 · 仅高波时看距MA20**

| 距MA20 | 结论 |
|---|---|
| **< −1.81%**（超跌/中间） | **唯一有强证据的两格**：+0.917 / +0.695 |
| > −1.81%（贴近/上方） | 转负 −0.426，不要买 |

> 一句话：**高波 + 跌到均线下方 = 唯一有证据的组合；低波 + 超跌 = 最该避开的组合。**

### 这张卡的正当用法是"否决"，不是"买入"

1. **幅度太小**：最好的格 10 日 **+0.917pp**，而单笔 10 日收益 SD = **8.72pp** —— **噪声是信号的 9 倍**
2. **扣成本后所剩无几**：双边 0.1~0.2% 直接吃掉 11~22%
3. **样本内**：300 只 × 2016-2026，无样本外验证。且**同一因子在全样本里方向会翻转**（ATR 全样本 Q1 +0.119 → Q5 −0.391）
4. **"少量试仓"这个说法本身是信号**：如果信号够强，你会想"多买"而不是"少量"

✅ 正确用法：**ATR < 2.69% → 直接放弃**（证据最强，|t|>2.9 覆盖整行）；
　　　　　　　**高波但已回到均线上方 → 降级观察**
❌ 错误用法：看到"高波+超跌"就试仓

> 注意：这张卡的方向**与系统现在的 A/B 相反**——A 要求"回踩到均线"
> （即"贴近/上方"那一列，实测 −0.237~−0.426），且 A 通过时通常不是高波。
> **这就是 A 整体效应为负的原因。**

## ⚠️ ETF 与个股：用**不同的信息**判定

你的自选 20 只里有 8 只是 ETF。**别把个股那套因子套到 ETF 上** —— 两者可用的信息完全不同。

| 信息层 | 个股 | ETF | 说明 |
|---|---|---|---|
| **择时（PANIC_DOWN）** | ✅ 适用 | ✅ **适用，且最直接** | 状态由指数判定，与标的无关；宽基 ETF 是它的天然载体 |
| **双因子判读卡** | ✅ 三个前提下适用 | ⛔ **不适用** | 卡的样本是 300 只**个股**，内含 **0 只 ETF** |
| **SURVIVABILITY 价格否决** | ✅ 生效（<3元） | ⛔ **已豁免** | ETF 无面值退市；0.6 元的 ETF 不会因价格低而退市 |
| **SURVIVABILITY 流动性否决** | ✅ 生效 | ✅ 生效 | 流动性对两者都重要 |
| **A/B/C 选股边际** | ≈ 0（实测 −0.063%，t=−0.74） | 不适用 | 你的盈利不来自这里 |

### 为什么判读卡对 ETF 不适用（三个理由）

1. **样本里没有 ETF**：universe 只含 600/601/603/605/000/001/002/003/300/301/688/689 段，
   判读卡的分档边界（ATR 2.69/3.91、距MA20 −5.31/−1.81）全是在个股上测得的分位
2. **量级不可比**：ETF 净值 0.6~1.6 元 vs 个股 10~30 元，波动与偏离的分布根本不同
3. **混算百分位是类别错误**：把 ETF 和个股放进同一个横截面算排名没有意义
   —— 所以打分 CLI 与台账**已把 ETF 排除出排名**，显示为 `n/a(ETF)`

### 那 ETF 该看什么？

**回到你自己的账本**（2026-08-03 ~ 08-31）：

| | 轮次 | 净盈亏 | 胜率 |
|---|---|---|---|
| **ETF** | 6（成本完整） | **+123,973 元** | 100% |
| **个股** | 29（成本完整） | **−17,384 元** | 48.4% |

**赚在 ETF 主题，亏在个股。** 而 ETF 那条线目前**没有可用的量化因子**（判读卡不适用）。
所以对 ETF，现阶段可行的只有：

1. **择时**：PANIC_DOWN 时加仓宽基 ETF，持有约 20 个交易日
2. **你自己的主题判断**：那 +12.4 万是它赚出来的，不是系统的任何一个因子
3. **不要**把个股的判读卡、A/B/C、`-p` 档位硬套上去

> 如果你要检验"ETF 该怎么挑"，需要**单独在 ETF 样本上测一遍因子** —— 那是另一轮工作，
> 目前没有任何 ETF 侧的因子被验证过。

## 📘 ETF 使用说明（主题锚指数）

### 三条命令

```bash
# ① 单只 ETF：--etf 进入 ETF 模式（切主题锚 + 放宽放量倍数）
uv run python services/calc_indicators/main.py 512760 --no-weekly --etf

# ② 免记参数：--auto-etf 按代码段自动识别 ETF
uv run python services/calc_indicators/main.py 512760 --no-weekly --auto-etf

# ③ 临时指定锚（覆盖主题规则）：--index
uv run python services/calc_indicators/main.py 512760 --no-weekly --etf --index sh000300

# ④ 科创/半导体类改用科创50（默认是创业板指）
uv run python services/calc_indicators/main.py 512760 --no-weekly --etf --kc50
```

**日常只需要第 ② 条**（或把 `AUTO_ETF_MODE=true` 写进 profile，就不用每次带参数）。

### 它自动做了什么

跑 ETF 时会看到：

```
  ℹ️  512760 名称：国泰CES芯片ETF
  🧾 代码: 512760  |  标的指数: sz399006（创业板指(主题锚:芯片)）
  ⚠️  512760 原标的指数不在 baostock 覆盖内，已按**主题**改用 创业板指(主题锚:芯片) 作为锚…
```

| 步骤 | 说明 |
|---|---|
| 1. 取名称 | baostock `query_stock_basic`，本地缓存 `data/cache/etf_names.json`（只取一次） |
| 2. 匹配主题 | 按名称关键词查 `config.THEME_INDEX_RULES`，先命中先用 |
| 3. 切锚 | 维度B 大盘过滤 与 **维度E 市场状态** 都改看该主题锚 |
| 4. 放宽 | **只**放宽放量倍数 1.5 → 1.25 |

**为什么不能直接用 ETF 自己的标的指数**：行业主题 ETF 的精确指数（如中证全指半导体）
**baostock 没有**，原先一律兜底到上证综指 —— 等于**拿半导体 ETF 看整个上证的天气**。
实测两者恐慌日重合度仅 **34%**（漏掉 56% 的主题级恐慌日、误报 41% 的无关恐慌日）。

创业板指的择时已实测两段同号（2016-2020 +1.60pp、2021- +1.13pp）。

### ⚠️ 四条必读

1. **这是"代理锚"，不是精确标的指数**。输出里会标 `(主题锚:xxx)`。它比"看上证综指"准得多，但仍是近似。
2. **黄金/商品类 ETF 的锚意义有限**——黄金与 A 股低相关，任何 A 股指数都不是好锚。输出会带 `⚠️商品类` 警示。
3. **科创50（sh000688）已可用** —— baostock 没有它，但已接入**腾讯源**（`akshare.stock_zh_index_daily_tx`）兜底，`--kc50` 与 `--index sh000688` 都能正常取数。
   > 腾讯源是**非东财供应商**，且用显式 `sh000688` 形式——顺带消除了 efinance 那条路径的隐患：efinance 只认纯数字，`000688` 会被解析成**深市个股「国城矿业」**，一旦东财通道恢复可能**静默返回个股数据**。
4. **宽基 ETF 不受主题规则影响**：`510300→沪深300`、`510500→中证500` 等已核对的映射优先级更高，不会被改。

### 想改锚？**改 config 就行**

编辑 `services/calc_indicators/config.py`：

```python
THEME_INDEX_RULES: tuple = (
    # (关键词元组, 指数代码, 指数名) —— 按顺序匹配，先命中先用
    (("半导体", "芯片", ...), "sz399006", "创业板指"),   # 改这里
    ...
)

# 或精确指定某只（优先级最高，绕过关键词匹配）
ETF_INDEX_OVERRIDE: dict = field(default_factory=dict)
# 例：ETF_INDEX_OVERRIDE = {"512760": ("sh000300", "沪深300")}
```

| 你想做的 | 改哪里 |
|---|---|
| 换某类主题的锚 | `THEME_INDEX_RULES` 里对应那一行的第 2、3 项 |
| 给某只 ETF 单独指定 | `ETF_INDEX_OVERRIDE`（优先级最高） |
| 新增主题关键词 | 在 `THEME_INDEX_RULES` 加一行（**具体规则放前面**） |
| **科创/半导体换用科创50** | `--kc50` 或 `-o THEME_ANCHOR_KC=kc50` |
| 临时改一次 | `-o BENCHMARK_INDEX=sh000300` |
| 整体关掉 | `-o ETF_THEME_ANCHOR_ENABLED=false` |

**改完必跑验证**：

```bash
uv run python services/calc_indicators/verify_etf_mode.py --offline   # 应 24/24
uv run python services/calc_indicators/verify_etf_mode.py             # 应 27/27
```

### 科创主题：选创业板指还是科创50？

**默认创业板指。** 用 `--kc50` 可切科创50，但**两者各有胜场**（2026-10-01 实测）：

| 持有期 | **创业板指** | p | **科创50** | p |
|---|---|---|---|---|
| 1 日 | +0.22pp | 0.125 | −0.02pp | 0.510 |
| **3 日** | −0.16pp | 0.645 | **+1.26pp** | **0.040 ✅** |
| 5 日 | −0.00pp | 0.445 | +1.62pp | 0.065 |
| 10 日 | +0.42pp | 0.330 | +1.60pp | 0.155 |
| **20 日（默认）** | **+0.97pp** | 0.270 | +0.58pp | 0.335 |
| 40 日 | −0.59pp | 0.595 | +1.16pp | 0.355 |

**结论：短持有期用科创50，默认持有期（20日）用创业板指。**

为什么默认不给科创50：

| 判据 | 创业板指 | 科创50 |
|---|---|---|
| 双体制校验 | ✅ 2016-2020 +1.60 / 2021- +1.13 **两段同号** | ❌ 基日 2019-12-31，**2020 才有数据，无法校验** |
| 历史长度 | 3966 根 | 1636 根 |
| 恐慌事件数 | 96 天 / 47 段 | 39 天 / 19 段（功效约 1/3） |
| 默认持有期效应 | +0.97pp | +0.58pp（不显著） |

**怎么切：**

```bash
uv run python services/calc_indicators/main.py 512760 --no-weekly --etf --kc50
# 等价于
uv run python services/calc_indicators/main.py 512760 --no-weekly --etf -o THEME_ANCHOR_KC=kc50
```

**注意 `--kc50` 只影响半导体/芯片/科创/消费电子**（`$KC` 占位符那几个关键词），
**云计算/软件/计算机仍走创业板指**——因为它们不是科创50 的主要权重。

### 新买的 ETF 要登记吗？——**不用**

匹配是**按名称关键词**的，不是按代码。新 ETF 只要名字含关键词（如"半导体""芯片""电网"）
就自动匹配。**只有两种情况需要动手**：

1. 名字里的关键词不在表里 → 往 `THEME_INDEX_RULES` 加一个词
2. 关键词匹配错了 → 用 `ETF_INDEX_OVERRIDE` 精确指定

**不需要逐只登记代码**，所以换主题不用"补齐"。

### Step 5 · 分析台账（客观结论）


输出五节，分别回答不同问题：

| 输出节 | 回答什么 |
|---|---|
| 维度组合（仅 C / 仅 A / A+B+C） | **C 能不能用** |
| 门控否决 | SURVIVABILITY / RR 拦下的那批后来怎样 |
| **A 的失败原因分档** | **系统哪里可以改进**（放宽哪个阈值） |
| **C 的止损距离分档** | C 是不是靠极紧止损过关 |
| **双因子打分 vs A/B/C** | **两套口径谁更准**（并行观察的闭环） |
| **买 vs 没买** | **我的判断加了多少分** |

## 每月 · 盈亏归因（把流水和台账拼起来）

```bash
uv run python scripts/attribute_pnl.py
#   默认取 data/reports/ 下最新的资金流水 + data/observations/signal_ledger.csv
```

它回答**唯一重要的问题**：

> **我赚的钱，是系统挑出来的，还是我自己挑出来的？**

按三个互斥桶分账：

| 桶 | 含义 |
|---|---|
| **系统标记** | 台账里该标的在「本轮买入窗口内」有标记行 |
| **系统未标记** | 台账覆盖了该时段，但窗口内无标记 → **你自己挑的** |
| **台账未覆盖** | 台账当时根本没在记录（早期数据） |

**⚠️ 两个前提**：
1. **必须跑过 `autofill_ledger_bought.py`**，否则 `bought` 列是空的
2. **台账与流水的日期必须重叠**。台账从今天才开始记，而流水是过去的交易——
   这时全部轮次会落进「台账未覆盖」，脚本会明确告诉你"**现在还算不出归因**"
   （这不是"系统没用"的结论）。此时唯一能看的只有【二、ETF vs 个股】——
   **而这一栏已经足够回答"edge 在哪条线上"**。

## 两个对照别混用

```
· index 对照 =『这笔比我直接买指数好吗』→ 含 beta 与择时，贴近实际决策
· pool  对照 =『这笔比同期其它票好吗』→ 剥离大盘，纯选股能力
```

**某组若跑赢指数却输给同期同侪 → 那是 beta/择时，不是选股。**
（实测出现过："仅 A 通过"对指数 +0.93pp，但对同日同侪 −0.32pp。）
