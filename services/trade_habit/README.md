# TradeHabitMVP 交易习惯约束器

本地 Tkinter GUI 应用，**约束短线交易坏习惯**，而不是预测行情。半自动：所有决策由人点击完成，系统只负责计算、校验、记录、提醒、统计。

## 一、运行方式

### 1.1 环境要求

- Python 3.11+（项目根 `.python-version` 指定 `3.11`）
- Tkinter：随标准库安装
  - macOS 默认 Python（python.org 安装包）自带
  - Homebrew Python 需 `brew install python-tk`
  - Ubuntu/Debian 需 `sudo apt install python3-tk`
  - Windows 官方 Python 安装时勾选 "tcl/tk and IDLE" 即可

### 1.2 启动命令

```bash
cd services/trade_habit
python main.py
```

> **零第三方依赖**：不需要 `uv run`、不需要 `uv sync`、不需要 `pip install` 任何包。直接 `python main.py`。

### 1.3 数据库位置

首次启动后自动生成：

```
services/trade_habit/trade_habit.db
```

SQLite 单文件，包含 6 张表：

| 表名 | 作用 |
|------|------|
| `settings` | 键值配置（账户资金、单笔风险比例、日亏上限、日交易次数上限、情绪标签） |
| `stock_pool` | 股票池 |
| `trade_plan` | 计划单 |
| `trade_log` | 交易日志 |
| `checklist_run` | 检查清单执行记录 |
| `red_flag_event` | 红灯事件（覆盖、删除等） |

备份：直接复制 `trade_habit.db` 即可。

### 1.4 首次启动默认设置

| key | 默认值 | 含义 |
|-----|--------|------|
| `account_balance` | 100000 | 账户资金（元） |
| `risk_per_trade_pct` | 0.5 | 单笔风险比例（%） |
| `daily_max_loss` | 1000 | 单日最大亏损（元） |
| `daily_max_trades` | 3 | 单日最大交易次数 |
| `emotion_tags` | 平静,焦虑,贪婪,恐惧,无聊,急躁 | 情绪标签 |

可在「设置」Tab 修改并立即生效。

## 二、5 个 Tab 功能

### 2.1 仪表盘

显示：

- 今日入场次数（今日 `trade_log.entry_time` 当天的记录数）
- 今日已实现盈亏（今日 `trade_log.exit_time` 当天的 `pnl_amount` 之和，负数显示红色）
- 计划执行率（今日 `checklist_run.all_passed=1` 占总数比例，无数据显示 `—`）
- 红灯覆盖次数（今日 `red_flag_event` 数量）
- 当前红黄绿灯（绿/黄/红 大色块 + 原因说明）

**红黄绿灯规则**：

| 颜色 | 触发条件 |
|------|----------|
| 绿 | 正常 |
| 黄 | 今日已实现亏损 ≤ -日亏上限×80%，或今日入场次数 ≥ 日交易次数上限×80% |
| 红 | 今日已实现亏损 ≤ -日亏上限，或今日入场次数 ≥ 日交易次数上限 |

> 红灯时，检查清单第 8 项「当前无红灯」自动不通过，强制走覆盖流程。

### 2.2 股票池

表格列：ID、代码、名称、逻辑、关键位、催化剂、风险、状态、更新时间。

按钮：新增、编辑、删除、刷新、导入 CSV、导入 JSON、批量转可交易。

**状态枚举**：`观察` / `可交易` / `剔除` / `待确认`
- 手动新增/编辑只能选前 3 种（Combobox 不含 `待确认`）
- CSV/JSON 导入的行默认 `待确认`（淡黄背景高亮）
- 必须用「批量转可交易」按钮显式确认后才能用于计划单

### 2.3 计划单

表格列：ID、代码、名称、入场触发、入场区间、止损、时间止损、目标、计划股数、最大亏损、状态。

按钮：新增、编辑、删除、运行检查清单并入场、记录出场、取消计划、复制条件单提醒、导出 CSV、刷新。

**新增/编辑必填**：股票代码、入场触发条件、止损价、时间止损日期、计划股数、最大亏损金额。

**仓位建议计算器**（编辑弹窗内实时显示）：

```
单笔风险金额 = account_balance * risk_per_trade_pct / 100
每股风险 = abs(入场价上沿 - 止损价)
建议股数 = floor(单笔风险金额 / 每股风险 / 100) * 100
建议最大亏损 = 建议股数 * 每股风险
```

警告：若建议最大亏损 > 单笔风险金额，红字提示；若用户填入的 `max_loss_amount` > 单笔风险金额，检查清单第 6 项自动不通过。

**多头规则**：若 `止损价 >= 入场价上沿`，校验失败。

**状态流转**：`草稿 → 待触发 → 已入场 → 已结束`；任何状态可 → `取消`（除「已结束」外）。

#### 检查清单 8 项

点击「运行检查清单并入场」弹出检查清单窗口：

| # | 检查项 | 类型 | 判断方式 |
|---|--------|------|----------|
| 1 | 股票在股票池且状态为「可交易」 | 自动 | 查 `stock_pool` 表 |
| 2 | 已创建完整计划单 | 自动 | 计划存在且 status != '草稿'，关键字段非空 |
| 3 | 入场触发条件已满足 | 人工 | 用户勾选 |
| 4 | 止损价明确且可执行 | 人工 | 用户勾选 |
| 5 | 时间止损已设定 | 人工 | 用户勾选 |
| 6 | 仓位/最大亏损未超单笔风险上限 | 自动 | `plan.max_loss_amount <= account_balance * risk_pct / 100` |
| 7 | 今日交易次数未超上限 | 自动 | `today_entries < daily_max_trades` |
| 8 | 当前无红灯 | 自动 | `traffic_light != 'red'` |

- 全部通过：「确认入场」按钮可点
- 未全通过：必须点「覆盖并记录原因」，填非空原因 → 写 `red_flag_event` + `checklist_run(all_passed=0, override_reason=reason)` → 允许继续入场

#### 入场弹窗

确认后填：实际入场时间、入场价、数量、费用。

→ 创建 `trade_log`（exit_* 字段 NULL）→ 计划状态改 `已入场`

#### 出场弹窗

「记录出场」按钮（仅 `已入场` 可点），填：

- 出场时间、出场价、费用
- 是否按计划（1/0；选 0 时偏差原因必填）
- 偏差原因
- 情绪标签（取自 `settings.emotion_tags`）
- 情绪强度 1-10
- 备注

→ 计算 `pnl_amount` 和 `pnl_r` → 更新 `trade_log` → 计划状态改 `已结束`

#### 复制条件单提醒

把当前计划单转成文本并复制到剪贴板：

```
代码：600000
名称：浦发银行
入场触发：突破 10.20 且放量
止损：9.80
时间止损：2026-09-20
目标：11.00
计划股数：1000
最大亏损：400
请到券商 App 手动设置条件单/警报。
```

### 2.4 交易日志

表格列：ID、计划ID、代码、名称、入场时间、入场价、数量、出场时间、出场价、盈亏、盈亏R、是否按计划、偏差原因、情绪、强度。

按钮：编辑（补全出场/情绪/备注）、删除、导出 CSV、刷新。

**盈亏R 公式**：

```
pnl_amount = (exit_price - entry_price) * shares - fees
初始风险 = abs(entry_price - stop_loss) * shares
pnl_r = pnl_amount / 初始风险  （初始风险=0 时返回 0.0）
```

**导出 CSV**：编码 utf-8-sig，Excel 可直接打开。默认文件名 `trade_logs_YYYY-MM-DD.csv`。

### 2.5 设置

可修改：账户资金、单笔风险比例 %、单日最大亏损、单日最大交易次数、情绪标签（逗号分隔，下方实时预览解析后列表）。

保存校验：

- `account_balance > 0`
- `risk_per_trade_pct ∈ [0, 100]`
- `daily_max_loss >= 0`
- `daily_max_trades ∈ [1, 100]`
- `emotion_tags` 非空

保存后立即生效（仪表盘红黄绿灯实时重算）。

## 三、外部对接预留

支持 CSV/JSON 导入股票池：

- CSV：UTF-8 with BOM 优先，回退 UTF-8 / GBK；列名兼容 `code/Code/代码`、`name/Name/名称` 等
- JSON：支持 `[{...}, {...}]` 数组 或 `{"pool": [...]}` / `{"stock_pool": [...]}` 对象
- 导入的行默认状态 `待确认`，必须用「批量转可交易」按钮显式确认后才能创建计划单
- **不支持**直接通过导入创建计划单或交易日志

## 四、操作顺序

1. **首次启动**：用户在「设置」Tab 修改账户资金、单笔风险比例、日亏上限、日交易次数上限、情绪标签
2. **盘后**：手动新增股票池（默认「观察」），或导入外部 CSV/JSON（默认「待确认」）
3. **盘前**：把股票池状态改为「可交易」，从可交易股票创建计划单。系统自动计算建议股数和最大亏损
4. **盘中**：计划单触发后，点「运行检查清单并入场」。8 项全过才允许入场；未全过必须覆盖并记录原因
5. **入场**：填实际入场时间、价格、数量、费用，生成 trade_log，计划单状态改「已入场」
6. **持仓**：到达止损、时间止损、目标或逻辑破坏，用户手动记录出场。系统计算盈亏和盈亏R，计划单改「已结束」
7. **盘后**：补充偏差原因、情绪、备注。仪表盘显示今日交易次数、盈亏、计划执行率、红灯覆盖次数、红黄绿灯
8. **月末**：导出交易日志和计划单 CSV，人工对账招商流水，交给 AI 分析，只修正 1-2 条下月规则

## 五、核心约束

- 没有计划单，不允许入场
- 没有止损，不允许入场
- 红灯默认禁止入场
- 所有覆盖必须记录原因
- 所有出场必须记录是否按计划和情绪

## 六、未实现项

1. 多账户支持（当前 settings 仅一组账户参数）
2. 券商 API 自动同步（所有成交价手动录入）
3. AI 分析自动接入（仅提供 CSV 导出，后续可交给 AI 处理）
4. 历史回测（trade_log 仅记录实盘，不含回测标记）
5. 多周期统计（仪表盘仅显示今日，未实现周/月统计）
6. 止损执行率单独统计（当前以「是否按计划」间接体现）
7. 跨日持仓跟踪（plan 与 trade_log 是 1:1，未实现加仓/分批出场）
8. 数据备份/恢复 UI（用户可手动复制 `trade_habit.db` 文件备份）
