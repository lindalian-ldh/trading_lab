# Alarming Monitor — A股多维度量化预警与板块轮动系统

个人版 A 股市场大跌预警监控 + 板块轮动分析一体化工具。整合 **7 大原子风险信号（S1\~S7）**、**ADX 市场状态动态过滤**、**RRG 板块轮动四象限 + 5 维评分卡** 三大核心模块，输出 Markdown 全景报告与 CSV 历史记录。

## 二、模块一：7 大原子预警信号（S1\~S7）

每个信号返回统一结构：`{name, label, red(bool), value, threshold, detail, data_sufficient, red_reason}`；`red_reason` 仅在红灯时填充简短子分类（如 S6 的"过热"/"去杠杆"、S7 的"周线高位死叉"），数据不足时 `red=False, data_sufficient=False`（灰灯，不阻断）。亮灯信号行展示格式：`SX（名称·red_reason）`。

### S1 成交额 / 总市值占比过高

- **逻辑**：`两市总成交额 / A 股总市值 > TURNOVER_RATIO_THRESHOLD`

- **默认阈值**：3.0%（`TURNOVER_RATIO_THRESHOLD=0.030`）

- **总市值来源**：新浪 spot 无总市值列时，用 `TOTAL_MARKET_CAP=1.05e14`（105 万亿）配置常量兜底

- **成交额来源**：新浪指数 spot 的 `sh000001 + sz399001` 成交额列求和（元）

### S2 放量不涨

- **逻辑**：`近5日日均成交额 > 近20日日均成交额 × VOLUME_HIGH_MULT` **且** `沪深300近5日涨幅 ≤ INDEX_FLAT_PCT`

- **默认阈值**：量比 ×1.3，涨幅 ≤0

- **口径修正**：日均 ÷ 日均（旧版"5 日总量 vs 20 日日均"存在量级差 ×5 会持续误灯）

### S3 涨跌家数比从高位快速回落

- **逻辑**：`max(ad_ratio[-20:]) > AD_HIGH_REF` **且** `ad_ratio[-1] < AD_LOW_THRESHOLD`

- **默认阈值**：20 日内曾 > 2.5，今日跌破 1.0

- **历史序列来源**：legu 仅提供今日快照，由 `storage.append_breadth_today + read_breadth_history` 自累积 CSV 重建近 20 日序列（升序，末值今日）

### S4 高股息逆势走强

- **逻辑**：`沪深300近20日涨幅 < 0`（市场跌）**且** `高股息篮子绝对正收益` **且** `(高股息篮子涨幅 - 成长篮子涨幅) > DIVIDEND_SPREAD_PCT`

- **默认阈值**：高股息绝对收益 > 0，超额成长 > 3%

- **高股息篮子**（2 只）：银行ETF(512800)、公用事业ETF(516070)

- **成长篮子**（9 只）：芯片 / 计算机 / 机器人 / 创新药 / AI / 半导体 / 卫星 / 航空航天 / 军工

### S5 成长股破位

- **逻辑**：`成长篮子近20日涨幅 < GROWTH_BREAK_PCT` **或** `成长篮子今日均价 < 近20日均价均值`（跌破 20 日均线）

- **默认阈值**：近 20 日涨幅 < -5%

### S6 两融杠杆异常（融资融券资金面信号）

通过跟踪全市场融资融券余额的变化与杠杆水平，识别资金面"快速加杠杆（过热）"或"被动去杠杆（踩踏前兆）"两种异常状态。S6 与 S1~~S5 相互正交：S1~~S5 看的是价格 / 量能 / 板块轮动等市场表现维度，S6 看的是**杠杆资金**这一风险偏好最高的资金群体——他们一进一退往往领先于指数拐点。

- **逻辑**：分**过热**与**去杠杆**两条分支，各自有 1\~4 个子条件；任一分支命中即亮本分支；最终由 `MARGIN_RED_MODE`（默认 `OR`）合并 → 任一方向亮即 S6 亮红灯

- **过热分支**（任一命中即亮，提示"杠杆资金过度涌入，回调风险积累"）

  - 融资余额 5 日增速 > `MARGIN_GROWTH_5D`（默认 3%，快速加杠杆）

  - 融资余额 20 日增速 > `MARGIN_GROWTH_20D`（默认 8%，中期杠杆抬升）

  - 融资买入额 / 两市成交额 > `MARGIN_BUY_RATIO`（默认 12%，杠杆交易过热）

  - (融资余额 - 融券余额) / 总市值 > `MARGIN_NET_LEVERAGE`（默认 1.8%，净多头杠杆过高）

- **去杠杆分支**（任一命中即亮，提示"杠杆资金被动撤离，可能引发踩踏"）

  - 融资余额 5 日回撤 < `MARGIN_DELEV_5D`（默认 -2%）

  - 融资余额 10 日回撤 < `MARGIN_DELEV_10D`（默认 -3.5%）

- **红灯合并模式**：`MARGIN_RED_MODE`

  - `OR`（默认）：过热 OR 去杠杆任一命中即亮红

  - `BOTH`：仅双向共振（过热 AND 去杠杆同时命中）才亮红，适合做"极端信号"口径

- **value 取值优先级**：`净多头杠杆水平 → 5 日增速 → NaN`；`threshold` 对应同一指标的阈值，便于 CSV/Markdown 一致展示

#### 数据来源与获取流程

全市场两融汇总由 `data_loader.fetch_margin_summary` 组合 akshare 的两个接口得到，**单位统一为元**：

| 数据片段               | 主接口                                                   | 单位       | 备注                                                                                    |
| ------------------ | ----------------------------------------------------- | -------- | ------------------------------------------------------------------------------------- |
| 上交所（SSE）两融区间汇总     | `akshare.stock_margin_sse(start_date, end_date)`      | 元（int）   | 一次拉取 25+ 自然日，含融资余额 / 融资买入额 / 融券余额等                                                    |
| 深交所（SZSE）当日快照      | `akshare.stock_margin_szse(date=YYYYMMDD)`            | 亿（float） | 拉失败时回退 `stock_margin_detail_szse` 明细汇总；周末 / 节假日 / 数据未出可能报 length mismatch，自动 fallback |
| 总市值（S6 净杠杆分母）      | 复用 S1 的 `cfg.TOTAL_MARKET_CAP`（默认 1.05e14 元 = 105 万亿） | 元        | 与 S1 一致，避免维护两套兜底常量                                                                    |
| 两市成交额（S6 融资买入占比分母） | 复用 S1 拉取的新浪 `sh000001 + sz399001` 成交额                 | 元        | 一次拉取双用                                                                                |

获取流程（`fetch_margin_summary(ref_date, lookback_days=25, prefer_csv_df)`）：

1. **优先 CSV 自累积**：`storage.read_margin_history(days=25)` 读近 3 个月的 `margin_YYYY-MM.csv`，若覆盖到最新日且行数足够，则免拉 SSE（最热路径，0 触网）
2. **CSV 不覆盖或行数不足 → 补拉 SSE 区间**：`ak.stock_margin_sse(start_date, end_date)`，按列重命名（中文→`rzye/rzmre/rqye/rqmcl/rzrqye/rqyl`），单位走 `_margin_rows_to_yuan` 归一化（启发式：最大绝对值 < 1e6 视为亿，×1e8 转元）
3. **SZSE 当日快照补加**：循环今日 / 昨日 / 前日 3 天（应对非交易日 / 数据未出），拉到即停；按 `date` 与 SSE 序列合并——同日则数值列相加，未匹配则追加一行
4. **CSV 落盘**：`storage.append_margin_row` 把最新一行写入 `data/alarming_signals/margin_YYYY-MM.csv`（同日去重、按月分文件、跨月拼接）
5. **返回**：升序 DataFrame，列含 `date, rzye, rzmre, rqye, rzrqye, rqmcl, rqyl`，单位全为元；任一关键源失败返回 None（S6 降级为灰灯）

### S7 大盘 KDJ 高位死叉（周 / 月线中长周期形态信号）

通过沪深300日线**聚合到周线 / 月线**后计算国内版 KDJ 指标，识别"周线 K>80 时下穿 D"或"月线 K>80 时下穿 D"这种典型的**高位死叉**形态。S1\~S6 看的是当前日级别的量价/涨跌/板块/杠杆状态，S7 看的是**几周甚至几个月维度累积的超买顶部转折信号**——时间尺度更长，用来预警"趋势性大跌"而不是日内回调。

- **逻辑**：复用 `BREADTH_INDEX`（沪深300）日线数据 → `pandas.resample` 聚合周线('W')/月线('ME') → 国内版 KDJ 计算 → 在最近 `KDJ_DEATH_CROSS_LOOKBACK`（默认 3）个周期内扫描**高位死叉**（`K[i-1] ≥ D[i-1]` 且 `K[i] < D[i]` 且 `K[i-1] > KDJ_OVERBOUGHT`）→ 周/月两周期按 `KDJ_RED_MODE`（默认 `OR`）合并为最终红灯

- **默认阈值**（`config.AlarmConfig` 第 9 节）：

| 参数                                   | 默认值         | 含义                                      |
| ------------------------------------ | ----------- | --------------------------------------- |
| `KDJ_RSV_PERIOD`                     | 9           | RSV（未成熟随机值）计算周期                         |
| `KDJ_K_SMOOTH` / `KDJ_D_SMOOTH`      | 3 / 3       | K 和 D 的平滑周期（国内惯例 SMA(3,1)）              |
| `KDJ_OVERBOUGHT`                     | 80.0        | 高位阈值：死叉前一期 K > 80 才认定为"高位"死叉            |
| `KDJ_DEATH_CROSS_LOOKBACK`           | 3           | 死叉识别窗口（最近 N 个周期内发生过即算，避免"刚死叉那期数据未出就漏判"） |
| `KDJ_LOOKBACK_DAYS`                  | 260         | 日线拉取窗口（≥ 52 周 / 12 月，覆盖 1 年交易日足够）       |
| `KDJ_USE_WEEKLY` / `KDJ_USE_MONTHLY` | True / True | 是否启用周线 / 月线（任一关则仅用另一周期）                 |
| `KDJ_RED_MODE`                       | OR          | 合并模式：`OR`（任一周期高位死叉即红）/ `AND`（双周期共振才红）   |

- **国内版 KDJ 计算公式**（`_calc_kdj` 纯 numpy 自实现）：

```
RSV[i] = (close[i] - min(low[i-n+1..i])) / (max(high[i-n+1..i]) - min(low[i-n+1..i])) * 100
K[i] = (K[i-1] * (k_smooth - 1) + RSV[i]) / k_smooth   # 初始 K[0]=50
D[i] = (D[i-1] * (d_smooth - 1) + K[i])  / d_smooth   # 初始 D[0]=50
J[i] = 3*K[i] - 2*D[i]
```

- **高位死叉识别要点**：

  1. 只判定"最近 KDJ\_DEATH\_CROSS\_LOOKBACK（3）个周期"内是否发生过死叉——老历史的死叉不算（避免"2024 年牛市顶死叉但现在已是 2026 年"这种假阳性）
  2. 死叉必须**前一期 K 在高位**（`K[i-1] > 80`）——低位死叉（如 K 从 30 下穿 25）是"从弱走更弱"，不是高位反转，不亮红灯
  3. 周线/月线独立判定后按 `KDJ_RED_MODE` 合并：`OR` 任一中即红，`AND` 需双周期共振（更严苛的大顶信号）

- **red\_reason 子分类**（亮灯信号行展示）：

| 场景                               | red\_reason 示例                         |
| -------------------------------- | -------------------------------------- |
| 仅周线高位死叉                          | `周线高位死叉（K 94.9→84.9）`                  |
| 仅月线高位死叉                          | `月线高位死叉（K 92.1→79.8）`                  |
| 双周期共振（`KDJ_RED_MODE=AND` 才需同时命中） | `双周期高位死叉（周线K 94.9→84.9；月线K 92.1→79.8）` |

#### 实现流程（`indicators.check_kdj_divergence(index_df, cfg)`）

```
BREADTH_INDEX 日线（260 行，data_loader 拉取）
  └─→ _resample_ohlc(df, 'W')  ──周线 OHLCV
        └─→ _calc_kdj(n=9, k=3, d=3) ── 周 K/D/J 序列
              └─→ _find_recent_cross(周K, 周D, lookback=3, overbought=80)
  └─→ _resample_ohlc(df, 'ME') ──月线 OHLCV
        └─→ _calc_kdj(n=9, k=3, d=3) ── 月 K/D/J 序列
              └─→ _find_recent_cross(月K, 月D, lookback=3, overbought=80)
  └─→ 按 KDJ_RED_MODE 合并 → red=True/False + red_reason + detail + kdj_detail{branch_hits, k_now, mode}
```

关键说明：

- **周/月线聚合在 indicators 内完成**，不在 data\_loader 做——数据层只拉原始日线（便于缓存复用），指标聚合放纯函数层，逻辑一致、易测

- `_resample_ohlc` 兼容 pandas 新版：把 `'M'` 自动转 `'ME'`、`'Y'`→`'YE'`；按期末日期作为周期标签

- `KDJ_LOOKBACK_DAYS=260` 已在 `main._gather_data` 与 `VOLUME_LOOKBACK_DAYS / ADX_PERIOD / LOOKBACK_DAYS` 取 max 作为 `fetch_index_daily` 实际窗口，**不会为 S7 单独再拉一次指数数据**

- `value` 字段用主周期（月线优先→周线）的最新 K 值，便于 CSV 横向比较；`threshold` 对应 `KDJ_OVERBOUGHT`

#### 数据不足与降级

| 失败场景                                          | 信号表现                                         | 不阻断整体流程 |
| --------------------------------------------- | -------------------------------------------- | ------- |
| `index_df` 为空 / 缺 `high/low/close`            | 灰灯                                           | ✓       |
| 日线 < n+2 行（聚合后 KDJ 无法有效收敛）                    | 灰灯（仅对应周期灰，不影响另一周期）                           | ✓       |
| `KDJ_USE_WEEKLY` 和 `KDJ_USE_MONTHLY` 均为 False | 灰灯（未启用任何周期）                                  | ✓       |
| 周/月线聚合尾部有空 NaN 周期（周末/节假日区间无交易）                | `resample` 后 `dropna(subset=['close'])` 自动丢弃 | ✓       |

## 三、模块二：ADX 市场状态过滤器（动态阈值）

Wilder 平均趋向指标（`ADX_PERIOD=14`）衡量趋势**强度**（不关心涨跌方向），基于沪深300的 high/low/close 计算。作为**市场状态过滤器**，不直接亮红灯，而是动态调整红灯计数阈值与权重。

| 市场状态            | ADX 区间        | 动态阈值                             | 说明                                                                                                                                                             |
| --------------- | ------------- | -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 强趋势市 `trend`    | ADX > 30      | **5**（需全亮）                       | 情绪主导增量市场，轻度"放量不涨"会被后续资金消化                                                                                                                                      |
| 弱趋势/震荡市 `range` | ADX < 22      | **3**（S4/S5/S6 加权 ×1.5，S7 不参与加权） | 存量博弈，抽血效应 / 机构弃守 / 杠杆资金撤离更易引发踩踏；`effective_red_count = ceil(加权和)`。**S7 不纳入加权的原因**：它是周/月线级的中长周期形态信号（典型"大顶预警"），与 S4/S5/S6 这种"震荡市当日抽血/弃守/撤离"不在同一时间尺度，保持其独立强信号属性即可 |
| 过渡区 `neutral`   | 22 ≤ ADX ≤ 30 | **4**（维持原判）                      | 方向不明，严格口径                                                                                                                                                      |

- **talib 加速**：`USE_TALIB=True` 且 talib 可用时走 `talib.ADX`，否则降级纯 numpy `_compute_adx` Wilder 自实现（前 period 项简单平均初始化 + `S_t = S_{t-1} - S_{t-1}/n + X_t` 递推）

- **ADX 未取 / 数据不足**：退化为配置档自身 `REDUCE_THRESHOLD`（default=4, conservative=3, strict=4）

## 四、模块三：板块轮动分析（RRG 四象限 + 5 维评分卡）

### 4.1 时间轴全局对齐

`align_to_benchmark` 以沪深300交易日为**统一锚点**，所有 ETF 篮子成员按 `date` 左连接 + `ffill` 向前填充（停牌/节假日缺失复用前一日）。输出 ETF 行数严格 = len(bench\_df)，避免长度不齐导致指标错位。

### 4.2 板块篮子（36 只 ETF，可在 config 替换为个股）

**行业/主题 ETF（19 只，原有）**：防御（银行、公用事业）+ 成长（芯片、计算机、机器人、创新药、AI、半导体、卫星、航空航天、军工）+ 主题（电力、电网设备、能源、农业、豆粕、粮食、消费、医疗器械）。

**宽基指数 ETF（5 只，扩展）**：上证50(510050)、沪深300(510300)、中证500(510500)、创业板(159915)、科创50(588000)。

**行业/主题 ETF 扩展（12 只）**：证券保险、券商、酒、家电、有色金属、煤炭、化工、游戏、通信、恒生科技、港股创新药。

> 注意：510300 沪深300ETF 与基准同指数，RS-Ratio 恒为 1.0、RS-Momentum 恒为 0，轮动意义有限，可按需从篮子移除。港股 ETF（513180/513120）交易日历与 A 股不一致，由 ffill 对齐。

### 4.3 RRG 相对强度四象限

先对 ETF 收盘价与基准做**归一化**（各自首行有效值 = 1，解决 ETF 价格 \~0.8 vs 指数 \~4500 的量级差异问题），再取比值做 `WMA(20)` 得到 **RS-Ratio**（相对强度）；对 RS-Ratio 做 `ROC(10)` 得到 **RS-Momentum**（动量变化率 %）。

| 象限  | 组合条件                                 | 标签      | 含义           |
| --- | ------------------------------------ | ------- | ------------ |
| I   | RS-Ratio > 1.0 **且** RS-Momentum > 0 | 🟢 领涨主线 | 强强：强者恒强，优先持有 |
| II  | RS-Ratio ≤ 1.0 **且** RS-Momentum > 0 | 🟡 轮动初期 | 弱强：由弱转强，关注建仓 |
| III | RS-Ratio ≤ 1.0 **且** RS-Momentum ≤ 0 | 🔴 滞后回避 | 弱弱：持续弱势，回避   |
| IV  | RS-Ratio > 1.0 **且** RS-Momentum ≤ 0 | 🟠 退潮预警 | 强弱：盛极而衰，警惕   |

- **边界保守归类**（默认开启 `RRG_BOUNDARY_CONSERVATIVE=True`）：RS-Ratio=1.0 归入弱侧（≤1），RS-Momentum=0 归入负侧（≤0）

### 4.4 5 维评分卡（每维归一化 \[0, 5]，加权求和 → 综合 \[0, 5]）

| 维度          | 权重  | 指标                                     | 满分条件                      |
| ----------- | --- | -------------------------------------- | ------------------------- |
| 维1 相对动量     | 25% | RS-Ratio - 1（**分段映射**，见下）              | 分段：1.03→1分 / 1.10→3分 / 1.20→5分；RS<1 直接 0 分 |
| 维2 动量加速度    | 20% | RS-Momentum 二阶差分（mom₁ - 2·mom₂ + mom₃） | 二阶差分 5% 即 5 分；负值给 0       |
| 维3 ADX 趋势强度 | 20% | ETF 自身 Wilder ADX(14) + +DI/-DI 方向 | 分段：15→0 / 20→1 / 25→3 / 30→5；下跌方向乘 0.1 降权 |
| 维4 资金关注度    | 20% | **成交额历史分位**（60日，见下）                    | 分位>80% 即 5 分；<20% → 1 分   |
| 维5 拥挤度折扣    | 15% | 上涨偏离MA20>2×ATR 或 成交额分位>90% 扣 2 分；下跌偏离不扣分（标超卖） | 不拥挤 5 分；拥挤 3 分            |

- **维1 分段归一化**（A2 改进）：实战中 RS-Ratio 多在 0.9~1.15，旧版"超基准 0.5 即满分"会把领涨主线（RS≈1.05~1.15）压成 0.5~1.5 分的低分，导致评分与象限标签脱节。改用分段映射：`RS=1.03 → 1分`（轻微跑赢）、`RS=1.10 → 3分`（显著跑赢）、`RS=1.20 → 5分`（满分，强势主线），分段间线性插值，超过 1.20 封顶 5 分，RS<1.0 直接 0 分。配置项 `SCORE_REL_MOM_BREAKPOINTS`（旧 `SCORE_REL_MOM_FULL=0.5` 保留为废弃兼容字段）。

- **维3 ADX 分段映射 + 方向降权**（A3 改进）：ADX 只代表趋势强度，不辨方向——强下跌品种（-DI > +DI）也会因 ADX=30 拿满分，不合实战。原版用线性映射 `ADX/30 × 5` + 下跌方向乘 0.3 降权，问题：① 15 以下无趋势品种仍能拿 2.5 分（虚高）；② 0.3 降权后强下跌仍能拿 1.5 分（不该拿）。改用**分段强度 + 强方向降权**：

  | ADX | 强度分（不分方向） | +DI > -DI（上涨） | -DI > +DI（下跌） |
  | --- | -------------- | -------------- | -------------- |
  | ≤ 15 | 0（无趋势） | 0 | 0 |
  | 20   | 1.0（弱趋势启动） | 1.0 | 0.1 |
  | 25   | 3.0（趋势形成） | 3.0 | 0.3 |
  | 30   | 5.0（强趋势满分） | 5.0 | **0.5** |
  | > 30 | 5.0（封顶） | 5.0 | 0.5 |

  段间线性插值；下跌方向统一乘 `ADX_DOWN_PENALTY=0.1`——强下跌趋势最多拿 0.5 分，不再虚高。配置项 `SCORE_ADX_BREAKPOINTS`（旧 `SCORE_ADX_FULL=30.0` 保留为废弃兼容字段）+ `ADX_DOWN_PENALTY=0.1`。实测：[2026-09-11 实跑](#463-实例对照kc-profile-2026-09-11-空头格局) 中银行ETF（ADX=34.6↑）维3 拿 5 分满分、公用事业（ADX=31.4↓）只拿 0.5 分。

  > 设计意图：维3 只奖励"**有方向的上涨趋势**"。下跌趋势再强也不该加分（操作矩阵已通过象限地板/天花板处理减仓/清仓），这里给 0.5 分而非 0 是为了保留"强下跌后若有超卖反弹 +DI 转正"的可观察性——下跌极强品种若 +DI 上穿 -DI 触发超卖反弹三级确认，其 ADX 高分能反映"新一轮趋势形成"。

- **维4 成交额历史分位**：腾讯源 ETF 无基金份额数据，真实换手率不可得；而 `amount/(close*volume)` 是单位换算常数（close*volume ≈ amount），无横截面区分度。旧版用 MA5/MA20 量比（放量倍数），对低换手品种（银行/豆粕）天然偏低且无法跨品种比较。改用**成交额历史分位**（`calc_amount_percentile`）：今日成交额在过去 60 日序列中的百分位，反映"今日量能相对自身历史的热度"——不受品种量级影响（银行ETF分位90% = 芯片ETF分位90% = 各自相对自身历史都处于放量状态）。分段映射：`<20% → 1分`（缩量）、`50% → 3分`（正常）、`>80% → 5分`（放量），分段间线性插值。配置项 `SCORE_CAP_ATTENTION_LOOKBACK=60`、`SCORE_CAP_ATTENTION_LOW_PCT=20`、`SCORE_CAP_ATTENTION_HIGH_PCT=80`。

- **维5 拥挤度折扣改进（拆方向）**：旧版用 `|close-MA20|` 绝对值判断偏离，下跌偏离（超卖）也会扣分——但超卖是机会而非拥挤。改为**方向区分**：
  1. **上涨偏离**（`close > MA20` 且 `(close-MA20)/close > 2×ATR/close`）→ 扣 `CROWDING_PENALTY=2` 分（拥挤/回调风险）
  2. **下跌偏离**（`close < MA20` 且 `(MA20-close)/close > 2×ATR/close`）→ **不扣分**，标记 `oversold_flag=True`（超卖观察，进 4.6 节反弹分级系统）
  3. **成交额分位 > 90%**（极度放量）→ 扣分（拥挤）
  配置项 `CROWDING_PRICE_DEVIATION_ATR_MULT=2.0`、`CROWDING_AMOUNT_PCT_HIGH=90.0`。旧字段 `CROWDING_TURNOVER_THRESHOLD=2.5` 保留为废弃兼容字段。

- **超卖反弹观察系统**：维5 拆方向后，下跌偏离不再扣分而是标记超卖。新增**三级反弹分级**（不进总分，仅作操作参考的机会提示/降级保护），详见 [4.6 节](#46-超卖反弹观察系统)。

- **操作参考**：不再由总分一刀切，而是"象限标签定地板/天花板 + 大盘格局修正 + 波动率刹车 + 回避分级"四维矩阵，详见 [4.5 节](#45-操作参考象限地板天花板--大盘格局--波动率--回避分级)。

- **排名 Δ**：读取 `data/cache/rotation_rank_last.json` 上次排名缓存，与今日 `total_score` 排名做差，输出 `+N / -N / 持平 / 新`（首次运行全部"新"）

### 4.5 操作参考：双列动作（有仓位 / 无仓位）+ 象限地板天花板 + 大盘格局 + 波动率

> 这一节回答的问题是：**表格最右两列"有仓位"和"无仓位"是怎么算出来的？为什么同样是领涨主线，有仓位是"持有"而无仓位是"观望"？**

早期版本的操作参考只有一列，且只看 5 维总分三档（>4 持有/加仓、3~4 关注、≤3 回避），存在三个问题：
1. **领涨主线🟢 却"回避"**：豆粕 ETF 是领涨主线，但低换手导致维4 资金关注度拿不到高分，总分 ~2.7，命中"≤3 回避"——象限标签和操作参考各算各的，互不通气。
2. **全员回避无区分度**：震荡市/空头市下，19 只板块有 15+ 只评分都落在 2~3 区间，全部输出"回避"，交易员看不出该卖谁、该看谁。
3. **动作语义混淆"有仓"和"无仓"**："持有"对无仓位的人没有意义；"关注建仓"和"持有"不在同一维度——前者是"可以买"，后者是"已有仓位不动"。空头市领涨主线，有仓者应"持有"（不动），无仓者应"不新开"（观望），简单一个"持有"无法区分这两种语义。

为解决这三个问题，操作参考改为**双列输出 + 三维矩阵决策**：输出"有仓位动作"和"无仓位动作"两列，每列由"象限标签定方向、大盘格局定基调、波动率做风险刹车"共同决定。

#### 4.5.1 双列动作语义

| 列 | 含义 | 可取值 | 维度 |
| -- | ---- | ------ | ---- |
| **有仓位** | 已持有该板块ETF时的动作 | 持有 / 减仓 / 清仓 / 观望 | 卖或不卖 |
| **无仓位** | 未持有该板块ETF时的动作 | 可建仓 / 可轻仓 / 观望 / 回避 | 买或不买 |

**直觉解释**：
- **有仓位列**只回答"要不要卖"：持有=不动，减仓=卖一部分，清仓=全卖，观望=先看不动
- **无仓位列**只回答"要不要买"：可建仓=可以买，可轻仓=小仓试，观望=先看，回避=不碰
- 同一板块对有仓者和无仓者的建议可能完全不同：空头市领涨主线 → 有仓"持有"（已有仓位不动，不追加），无仓"观望"（大盘弱不新开仓位）

#### 4.5.2 三个决策因子

| 因子 | 来源 | 取值 | 作用 |
| ---- | ---- | ---- | ---- |
| **象限标签** | RRG 四象限（4.3 节） | 领涨主线🟢 / 轮动初期🟡 / 退潮预警🟠 / 滞后回避🔴 | 定**地板/天花板**：每个象限有最低和最高动作约束 |
| **大盘格局** | 基准收盘价 vs MA20/MA60（B5） | above 多头 / below 空头 / mixed 震荡 / unknown | 定**基调**：空头市全面防守，多头市可进攻 |
| **波动率** | ATR(14)/close × 100（B6） | high >3% / low <1.5% / medium 中等 / unknown | 做**风险刹车**：高波动时即便领涨也不建仓 |

> **注意**：波动率**不进入加权总分**，只作为操作参考的修正因子。原因——波动率高低本身不代表好坏（高波动可能是启动信号，也可能是见顶信号），只代表风险收益比。若作为评分维度，低波动品种（银行）永远拿高分、高波动品种（芯片）永远拿低分，又是另一种失真。

#### 4.5.3 象限标签的地板/天花板

"地板"= 该象限最低允许的动作（再差也不能低于此）；"天花板"= 该象限最高允许的动作（再好也不能超过此）。

| 象限 | 有仓位地板→天花板 | 无仓位地板→天花板 | 直觉解释 |
| ---- | --------------- | --------------- | ------- |
| 🟢 领涨主线 | 持有 → 持有 | 可轻仓 → 可建仓 | 强者恒强，有仓至少持有，无仓可建仓 |
| 🟡 轮动初期 | 观望 → 持有 | 观望 → 可轻仓 | 由弱转强，方向未明，不重仓但可小仓试 |
| 🟠 退潮预警 | 减仓 → 持有 | 观望 → 观望 | 盛极而衰，有仓减仓或持有，无仓不追 |
| 🔴 滞后回避 | 清仓 → 减仓 | 回避 → 回避 | 持续弱势，有仓清仓/减仓，无仓不碰 |

这条规则直接解决了"领涨主线却回避"——领涨主线的无仓位地板是"可轻仓"，**无论总分多低都不会输出"回避"**，最低也是"可轻仓"或经大盘修正后的"观望"。

#### 4.5.4 大盘格局修正（B5）

用基准指数（沪深300）收盘价 vs MA20/MA60 判定全局格局，对所有象限的动作做基调修正：

| 大盘格局 | 判定 | 领涨主线🟢 (有/无) | 轮动初期🟡 (有/无) | 退潮预警🟠 (有/无) | 滞后回避🔴 (有/无) |
| ------ | --- | ------- | ------- | ------- | ------- |
| **above 多头** | close>MA20 且 close>MA60 | 持有/可建仓 | 持有/可轻仓 | 持有/观望 | 减仓/回避 |
| **mixed 震荡** | 介于两者之间 | 持有/可轻仓 | 观望/观望 | 减仓/观望 | 清仓/回避 |
| **below 空头** | close<MA20 且 close<MA60 | 持有/观望 | 观望/观望 | 减仓/观望 | 清仓/回避 |
| unknown | 数据不足 | 保持象限基础动作 | 保持 | 保持 | 保持 |

**直觉解释**：
- **空头市（below）**：即便品种自身是领涨主线，有仓者"持有"已是最高动作（不追加），无仓者"观望"不新开仓位——大盘系统性下跌会拖累所有品种；轮动初期方向不明+大盘弱=有仓不动无仓不买；滞后回避+大盘弱=有仓清仓无仓回避。
- **多头市（above）**：领涨主线有仓持有无仓可建仓（系统性机会）；轮动初期有仓持有无仓可轻仓试错（大盘顺风）；退潮预警有仓持有无仓观望（大盘强可能扛住，但不追高）。
- **震荡市（mixed）**：领涨主线有仓持有无仓可轻仓（不重仓但可小仓试）；退潮预警有仓减仓无仓观望（趋势转弱+大盘不配合）。

报告顶部摘要会显示大盘格局元信息，例如：`...滞后回避 🔴4 只 · 大盘: 空头格局（均线下方，全面防守）`，让交易员一眼看出当前基调。

#### 4.5.5 波动率风险刹车（B6）

ATR(14)/close × 100 作为波动率代理（talib 加速 + numpy Wilder 平滑降级），典型区间：
- `< 1.5%` 低波动：稳健趋势，建仓风险收益比好
- `1.5%~3.0%` 中等波动：正常
- `> 3.0%` 高波动：风险收益比恶化，建仓需谨慎/降级

波动率对操作参考的修正规则：

| 波动率 | 领涨主线🟢 (有/无) | 退潮预警🟠 (有/无) | 轮动初期🟡 (有/无) |
| ---- | ------- | ------- | ------- |
| **高波动(>3%)** | 持有/观望（风险刹车，无仓不追） | 减仓/观望（加速撤离） | 观望/观望（先看不动） |
| **低波动(<1.5%)** | 持有/可建仓（健康趋势） | 正常 | 正常 |
| 中等/unknown | 正常 | 正常 | 正常 |

**直觉解释**：高波动+领涨=风险收益比恶化，有仓持有但不追加，无仓观望不追；高波动+退潮=波动放大下跌压力，有仓加速减仓；高波动+轮动初期=波动大方向不明，有仓无仓都先观望。

#### 4.5.6 完整决策矩阵（象限 × 大盘 × 波动率）

下表是 `_resolve_action` 函数的完整决策逻辑（`rotation.py`），格式为"有仓位 / 无仓位"：

| 象限 | below（空头） | mixed（震荡） | above（多头） |
| ---- | ---------- | ---------- | ---------- |
| 🟢 领涨主线 | 持有 / 观望 | 持有 / 可轻仓 | 持有 / 可建仓；高波动→持有/观望；低波动+高分→持有/可建仓 |
| 🟡 轮动初期 | 观望 / 观望 | 观望 / 观望 | 持有 / 可轻仓；高波动→观望/观望 |
| 🟠 退潮预警 | 减仓 / 观望 | 减仓 / 观望 | 高波动→减仓/观望；高分→持有/观望；否则减仓/观望 |
| 🔴 滞后回避 | 清仓 / 回避 | 清仓 / 回避 | 减仓 / 回避 |

> 兜底：当象限标签为 None（如单元测试直接调 `calc_5d_score` 不传象限）时，回退到旧总分三档（>4 持有/可建仓、3~4 持有/可轻仓、≤3 减仓/回避），保证兼容性。

**核心改进**：

4. **波动率刹车**：高波动时即便领涨也无仓观望（风险收益比恶化）

#### 4.5.8 设计意图

这套双列操作参考矩阵不是给你"明天买什么"的短线择时，而是板块相对强弱的中期筛选工具：

- **有仓位列**：回答"已有的仓位要不要动"——持有=不动，减仓=卖一部分，清仓=全卖，观望=先看不动
- **无仓位列**：回答"没有的仓位要不要建"——可建仓=可以买，可轻仓=小仓试，观望=先看，回避=不碰

双列分离的核心价值：**同一板块对有仓者和无仓者的建议可能完全不同**。空头市领涨主线，有仓者"持有"（已有仓位不动，不追加），无仓者"观望"（大盘弱不新开仓位）——单列输出无法表达这种差异，双列让交易员一眼看出"该不该动"和"该不该建"。

三维矩阵的本质是用**象限（品种强弱）× 大盘（系统性环境）× 波动率（风险收益比）**做交叉验证，避免单看总分被假突破或低换手误导。

### 4.6 超卖反弹观察系统

> 这一节回答的问题是：**表格最右两列"超卖"和"反弹"是怎么算的？为什么"滞后回避+超卖"仍是清仓，而"轮动初期+超卖候选"无仓变可轻仓？**

维5 拆方向后，下跌偏离（close < MA20 且偏离 > 2×ATR）不再扣分，而是标记 `oversold_flag=True`。但超卖本身不等于买入信号——下跌趋势中 MA20 下移，2ATR 偏离会反复触发，超卖可以更超卖。本系统对超卖做三级分级，不进总分，只作操作参考的"机会提示"和"降级保护"。

#### 4.6.1 三级条件

| 级别 | 条件 | 含义 | 动作 |
| ---- | ---- | ---- | ---- |
| **一级（观察）** | close < MA20 且 MA20-close > 2×ATR | 价格短期跌过头，但趋势未必止跌 | 只进观察池，不买 |
| **二级（候选）** | 一级 + 任一：①RS-Momentum>0 ②象限改善 ③分位从<20%回升到>50% | 下跌偏离 + 相对强度开始修复 | 无仓可列入候选，有仓不追杀 |
| **三级（确认）** | 二级 + 任一：①RS-Ratio回升+RS-Momentum>0连续2日 ②+DI上穿-DI ③分位>60%且站回MA5 | 超卖+相对强度+量能+短期价格结构同时改善 | 无仓可轻仓试错，有仓可持有观察 |

**象限改善**判断（昨日→今日）：
- 🔴滞后回避 → 🟡轮动初期（RS-Momentum 转正）
- 🔴滞后回避 → 🟠退潮预警（RS-Ratio 突破1.0）
- 🟡轮动初期 → 🟢领涨主线（RS-Ratio 突破1.0）
- 🟠退潮预警 → 🟢领涨主线（RS-Momentum 转正）

象限 rank 映射（`_classify_oversold_rebound`，[rotation.py#L711](file:///Users/a801/Linda/Work/project/gupiao-assistant/trading_lab/services/alarming_monitor/rotation.py#L711)）：
`{'滞后回避': 0, '轮动初期': 1, '退潮预警': 1, '领涨主线': 2}`，`today_rank > prev_rank` 即判改善。注意轮动初期与退潮预警同 rank=1，故 🟡↔🟠 之间不算改善（只是 RS-Ratio 与 RS-Momentum 的此消彼长，不算结构性升档）。

##### 判定伪代码

```python
# 维5 拥挤度（进总分）
crowding_penalty = 0
if close > ma20 and (close - ma20) / close > 2 * atr_pct:   # 上涨偏离
    crowding_penalty += 2
if amount_pct > 90:                                          # 极度放量
    crowding_penalty += 2

# 超卖观察（不进总分）
oversold = close < ma20 and (ma20 - close) / close > 2 * atr_pct

if not oversold:
    rebound_level = '无'
else:
    # ---- 时间约束（OVERSOLD_VALID_DAYS=5）----
    # 用 ATR_pct 全序列逐日判断超卖，找当前 streak 起点
    streak_start = find_oversold_streak_start(atr_pct_series, close_series, ma20_series)
    truncated = (streak_start <= max(19, period))         # 窗口起点保守不过期

    # streak 内找最近 RS-Momentum > 0 的日子 → 计时器归零
    last_pos_idx = find_last_positive(rs_mom_series, streak_start)
    if last_pos_idx >= 0:
        effective_days = today_idx - last_pos_idx         # 有正动量 → 从该日算
    else:
        effective_days = today_idx - streak_start + 1     # 无正动量 → 从起点算

    # 过期判定：effective_days > 5 且非 truncated → 置"无"
    if not truncated and effective_days > OVERSOLD_VALID_DAYS:
        rebound_level = '无'                               # 对外置"无"
        oversold_expired = True                            # 内部保留老化标记
    else:
        rebound_level = '观察'                             # 一级：仅价格跌过头
        # 二级：任一相对强度修复信号
        if rs_mom_today > 0 or quadrant_improved or amount_recovered:
            # 三级：任一确认信号
            if rs_ratio_recovered_and_mom_2d_pos or di_cross_up or (amount_pct > 60 and close > ma5):
                rebound_level = '确认'
            else:
                rebound_level = '候选'
```

> `atr_pct` = `calc_volatility_ratio` 返回的 ATR(14)/close × 100（百分比）；`amount_pct` = `calc_amount_percentile` 返回的成交额 60 日历史分位。时间约束用 `calc_atr_pct_series` 返回的完整 ATR_pct 序列逐日判断超卖，无需跨日持久化（方案 B：无状态重算，可回测、可复现）。

#### 4.6.2 与操作矩阵的耦合

超卖信号**不覆盖象限地板/天花板**，只做"机会提示"和"降级保护"。**大盘 below 时三级降一级**（确认→候选，候选→观察），避免接飞刀。

| 象限 | 有超卖信号时的处理 |
| ---- | --------------- |
| 🟢 领涨主线 | 少见，多为回调；有仓持有，无仓不因超卖加仓，等站回 MA20 |
| 🟡 轮动初期 | 最匹配；二级→无仓可轻仓试，三级→无仓可建仓（需大盘非 below） |
| 🟠 退潮预警 | 超卖不改变减仓；但三级+大盘 above 可从"减仓"降为"持有观察" |
| 🔴 滞后回避 | 超卖不改变清仓/回避；只进观察池，等象限转 🟡 再谈 |

**关键原则**：
- 滞后回避 + 超卖 ≠ 买入，只是"别追空"
- 轮动初期 + 超卖才是这套信号真正有用的地方
- 大盘 below 时，三级信号降一级处理

#### 4.6.4 已知陷阱与限制

1. **超卖可以更超卖**：下跌趋势中 MA20 下移，2ATR 偏离会反复触发。一级只能观察，不能买。
2. **ATR 本身在放大**：高波动品种 ATR 大，2ATR 偏离阈值也大，可能很少触发；低波动品种容易触发。建议叠加"偏离历史分位"做辅助（待实现）。实例对照中芯片/半导体偏离 5.9%~6.8% 却未触发超卖，就是因为 ATR 大（阈值 9.1%）。
3. **不替代止损**：滞后回避 + 超卖，有仓仍要按原规则清仓，不能因为"超卖"就扛单。
4. **时间约束已实现**（`OVERSOLD_VALID_DAYS=5`）：超卖信号触发后 5 日内未出现 RS-Momentum > 0 → 自动失效，`rebound_level` 置"无"，内部保留 `oversold_expired=True` + `oversold_days=N`。中途出现 RS-Momentum > 0 → 计时器归零重新计数。窗口起点已超卖 → `truncated=True` 保守不过期。过期后再次 RS-Momentum > 0 → 重新从观察/候选开始。报告评分列显示 `[观察 1/5]`（活跃）或 `[已失效 6/5]`（默认隐藏），摘要区分"活跃"和"已老化"。详见 [_classify_oversold_rebound](file:///Users/a801/Linda/Work/project/gupiao-assistant/trading_lab/services/alarming_monitor/rotation.py#L694-L923)。
5. **数据 NaN 导致 ATR 返回 nan**（已修复）：ETF 上市晚于基准时 align_to_benchmark 会让首行保留 NaN（正确行为），但旧版 `calc_volatility_ratio` numpy 降级路径未 dropna，导致 `tr[:period].mean()` 含 NaN 返回 nan，进而让维5 拥挤度/超卖检查全部被 `np.isfinite` 跳过——表现为"所有 ETF 超卖=否、反弹=无"。修复：在 ATR 计算前 `etf_df[['high','low','close']].dropna()`，并对最终 `atr` 加 `np.isfinite` 兜底。详见 [indicators.py#L1636-L1672](file:///Users/a801/Linda/Work/project/gupiao-assistant/trading_lab/services/alarming_monitor/indicators.py#L1636-L1672)。

#### 4.6.5 设计意图

这套系统的本质是让维5 从"只会扣分"变成"有罚有奖提示"：
- **罚**（进总分）：上涨偏离+极度放量 → 拥挤扣分（涨过头的风险）
- **奖**（不进总分，仅提示）：下跌偏离 → 超卖标记 + 反弹分级（跌过头的机会）

**时间约束**是这套"奖"机制的安全阀：超卖 5 日内无 RS-Momentum 转正 → 自动失效，避免观察池无限堆积导致交易员麻木化。计时器在 RS-Momentum 转正时归零，让"刚触发的超卖"和"已经老化 8 天还没反弹的超卖"区分开来。

系统对称性更好，也不会破坏现有评分和操作矩阵——超卖信号不覆盖象限地板/天花板，只做修正。

### 4.7 趋势/RS 健康度（拐点预警辅助）

> 这一节回答：表格最右三列"趋势健康"、"RS健康"、"拐点"是怎么算的？为什么"退潮预警+拐点改善"有仓从"减仓"降为"持有"，而"滞后回避+拐点改善"仍然清仓？

ADX 和 RS 单看"死值"容易误判拐点：ADX 高可能是强下跌也可能是强上涨；RS-Ratio 高可能见顶也可能刚启动。本节新增 5 个动态字段 + 2 个健康分 + 1 个拐点改善信号，**不进总分，只作"预警改善"提示和退潮降级保护**。

#### 4.7.1 新增字段

| 字段 | 公式 | 用途 |
| ---- | ---- | ---- |
| ADX斜率 | `ADX - ADX.shift(5)` | 趋势强度增强（>0）还是减弱（<0） |
| DI差 | `+DI - -DI` | 多方占优（>0）还是空方占优（<0） |
| RS动量加速度 | `RS_Mom - RS_Mom.shift(5)` | 相对强度加速（>0）还是减速（<0） |
| 多周期RS | `{5: rs, 20: rs, 60: rs}`（ETF收益-基准收益） | 5/20/60 日是否都跑赢基准，避免单周期骗人 |
| 成交量比 | `Volume / MA20(Volume)` | 今日涨跌是否放量（>1.5 放量，<0.8 缩量） |

#### 4.7.2 健康分（0~5，每项 +1 封顶）

**trend_health（趋势健康分）**：
1. ADX 斜率 > 0（趋势强度增强）
2. DI 差 > 0（+DI > -DI，多方占优）
3. +DI 上穿 -DI（多方接管）
4. ADX > 25（有趋势存在）
5. direction == 'up'（上涨趋势）

**rs_health（相对强度健康分）**：
1. RS 动量加速度 > 0
2. RS 动量最新值 > 0
3. 多周期 RS[5] > 0
4. 多周期 RS[20] > 0
5. 多周期 RS[60] > 0

#### 4.7.3 拐点改善信号（improvement_signal）

**三条件同时满足**才触发：

1. ADX 斜率 > 0（趋势强度增强）
2. +DI 上穿 -DI（多方接管）
3. RS 动量加速度 > 0（相对强度加速）

**与操作矩阵的耦合（仅作降级保护，不预测拐点）**：

| 象限 | 改善信号触发时的处理 |
| ---- | ------------------ |
| 🟠 退潮预警 | 有仓：减仓 → **持有观察**（不急于减仓，观察拐点是否成立） |
| 🔴 滞后回避 | 不变（仍清仓/回避，改善信号不改变清仓规则） |
| 🟡 轮动初期 | 不变（超卖反弹系统已处理建仓提示） |
| 🟢 领涨主线 | 不变（已是最强象限） |

> 设计意图：这一步**不预测拐点，只减少误判**。退潮预警品种如果同时出现"ADX 增强 + DI 上穿 + RS 加速"，可能是拐点前信号，给个"持有观察"的缓冲而非直接减仓；但滞后回避品种即使有改善信号也不清仓，因为破位品种的改善信号可靠性低。

配置项：`TREND_HEALTH_ADX_SLOPE_PERIOD=5` / `RS_MOM_ACCEL_PERIOD=5` / `RS_MULTI_PERIODS=[5,20,60]` / `VOLUME_RATIO_PERIOD=20`。

### 4.8 领先层（拐点提前嗅探）

> 这一节回答：表格最右列"领先"是怎么算的？为什么它是 0~100 分？哪些信号会让它升高？

4.6（超卖反弹）和 4.7（趋势/RS 健康度）都是"拐点已经发生后"的确认信号。领先层目标是**提前嗅到可能的拐点**——在价格还没动之前，从波动率压缩、量价背离、RS 动量背离三个维度捕捉"变盘前夜"的蛛丝马迹。

**输出 `lead_score`（0~100），只用于观察名单，不进总分、不改操作矩阵、不直接交易。**

#### 4.8.1 三类信号

| 类别 | 满分 | 触发条件 | 含义 |
| ---- | ---- | -------- | ---- |
| ① 波动率压缩 | 33 | ATR_pct 历史分位 < 20%（+17）**或** BBW 历史分位 < 20%（+16） | 盘整到极致，变盘前夜 |
| ② 量价背离 | 33 | 价格创 20 日新低但 OBV 不创新低（底背离）/ 价格创新高但 OBV 不创新高（顶背离） | 买盘承接 / 卖盘涌出 |
| ③ RS 动量背离 | 34 | 价格创 20 日新低，但 RS-Momentum 底部抬高（今日 > 窗口最低） | 相对强度先于价格修复 |

合计 0~100，三类信号互相独立可叠加。

#### 4.8.2 字段说明

| 字段 | 含义 |
| ---- | ---- |
| `lead_score` | 0~100 领先预警分 |
| `vol_compression` | 波动率压缩是否触发 |
| `vol_pct` / `bbw_pct` | ATR_pct / BBW 在过去 252 日的历史分位 |
| `price_obv_divergence` | `'bottom'` / `'top'` / `None` |
| `rs_mom_divergence` | RS 动量背离是否触发 |
| `lead_note` | 人类可读说明，如"波动压缩(ATR分位8%/BBW分位12%)；OBV底背离" |

#### 4.8.3 信号解读

- **0 分**：无领先信号，正常行情。
- **17~33 分**：单一信号触发（多为波动率压缩），加入观察名单，关注后续方向选择。
- **33~66 分**：两类信号叠加（如波动压缩 + 量价底背离），拐点概率上升，密切关注。
- **>66 分**：三类信号共振，变盘在即，重点观察但不直接交易（需结合象限/操作矩阵确认方向）。

> 设计意图：领先层是"侦察兵"不是"指挥官"。它告诉你"这里可能要变盘"，但不告诉你向上还是向下——方向仍由 RRG 象限和操作矩阵决定。领先层高分 + 退潮预警 → 可能见底反弹；领先层高分 + 领涨主线 → 可能见顶回调。具体动作仍由 4.5 操作矩阵决定，领先层只提供"提前量"。

配置项：`LEAD_LOOKBACK_DAYS=252` / `LEAD_VOLATILITY_LOW_PCT=20` / `LEAD_DIVERGENCE_WINDOW=20` / `LEAD_BOLLINGER_PERIOD=20` / `LEAD_BOLLINGER_STD=2.0`。

### 4.9 同步层（拐点确认，过滤假反弹）

> 这一节回答：表格最右列"确认"是怎么算的？为什么领先信号高分但确认分低时只观察不追？

4.8 领先层是"侦察兵"，告诉你"可能要变盘"。但领先信号可能是假的——波动率压缩后可能继续横盘，底背离后可能继续下跌。同步层的作用是**等市场确认再行动**，过滤假反弹。

**输出 `confirm_score`（0~100），5 个确认指标各 0~20 分，合计 0~100。不进总分、不改操作矩阵。**

#### 4.9.1 五个确认指标

| 指标 | 满分 | 确认条件 |
| ---- | ---- | -------- |
| ① MA20/MA60 | 20 | 价格站上 MA20（+10）**且** MA20 斜率转正（+10） |
| ② VWAP | 20 | 价格站上 VWAP（日线累积，典型价格×成交量加权） |
| ③ 成交量 | 20 | 今日量 > 20 日均量 × 1.5 倍 |
| ④ 价格结构 | 20 | 近 10 日高低点抬高（N 字突破） |
| ⑤ 板块宽度 | 20 | 近 20 日上涨天数占比 > 60% |

> 注：板块宽度原版要求"板块内 >60% 成分股上涨或站上 MA20"，但系统当前只有 ETF 数据没有成分股明细，因此用 ETF 自身近 N 日上涨天数占比近似。后续若接入成分股数据可替换。

#### 4.9.2 与领先层的耦合

| 领先分 | 确认分 | 状态 | 含义 |
| ------ | ------ | ---- | ---- |
| ≥ 50 | ≥ 60 | `turning_point_confirmed=True` | **拐点初步确认**：领先信号 + 市场确认共振 |
| ≥ 50 | < 60 | `turning_point_watch=True` | **只观察不追**：领先信号有，但市场未确认，可能假反弹 |
| < 50 | 任意 | — | 正常行情，无领先信号 |

#### 4.9.3 信号解读

- **0~40 分**：无确认或弱确认，领先信号即使出现也不可靠，继续观察。
- **40~60 分**：部分确认（如 MA 站上但未放量），可小仓试探。
- **60~80 分**：较强确认（MA + VWAP + 放量），结合领先高分可考虑建仓。
- **80~100 分**：全面确认（5 项中 4 项以上命中），趋势确立。

> 设计意图：同步层是"过滤器"不是"触发器"。它不产生交易信号，只决定领先信号是否可信。`lead_score 高 + confirm_score 低` 时绝不追入——这是过滤假反弹的核心规则。方向仍由 RRG 象限和操作矩阵决定，同步层只提供"可信度"。

配置项：`CONFIRM_MA_SHORT=20` / `CONFIRM_MA_LONG=60` / `CONFIRM_MA_SLOPE_PERIOD=5` / `CONFIRM_VWAP_PERIOD=20` / `CONFIRM_VOLUME_MA=20` / `CONFIRM_VOLUME_MULT=1.5` / `CONFIRM_PRICE_STRUCTURE_WINDOW=10` / `CONFIRM_BREADTH_WINDOW=20` / `CONFIRM_BREADTH_THRESHOLD=0.6`。

### 4.10 持有层（趋势延续判断，加仓/减仓/移动止损）

目标：拐点确认后，拿得住趋势。**只用于加仓/减仓/移动止损，不用于预测拐点**。
领先层（4.8）回答"拐点来了吗"，同步层（4.9）回答"拐点确认吗"，持有层回答"已持仓后拿得住吗"——三者各司其职，分数互不流入总分。

#### 4.10.1 三类长周期指标（合计 0~100 分）

| 指标 | 满分 | 触发条件 | 含义 |
|------|------|----------|------|
| ① 长周期 ADX | 34 | `ADX(56) > HOLD_ADX_THRESHOLD(20)` +17；`ADX 斜率 > 0`（rising） +17 | 季线级趋势存在且在增强 |
| ② 长周期 RS-Ratio | 33 | `RS(60) > HOLD_RS_STRONG(1.0)` +33 | 长期跑赢基准 |
| ③ 长周期均线 | 33 | 站上 `MA60` +16；站上 `MA120` +17 | 多头格局（季线 + 半年线） |

> 注：① 仅判断"ADX 是否有趋势且在增强"，**不判断方向**（+DI/-DI 由操作矩阵的象限标签处理）。下跌趋势中 ADX 也会高，但象限标签已是"滞后回避"，操作矩阵会优先清仓——持有层不做方向投票，只回答"趋势是否在延续"。

#### 4.10.2 离场信号：ATR 止损（优先级最高）

独立于 hold_score 阈值，**跌破即离场**：

```
stop_line = MA(20) - HOLD_ATR_STOP_MULT(2.0) × ATR(14)
atr_stop_broken = close < stop_line  →  hold_state = 'exit'
```

设计意图：移动止损是"机械执行"，不参考任何主观判断。无论领先/同步/总分多高，止损一破就走——这是风控底线。

#### 4.10.3 持有/减仓决策

| 状态 | 条件 | 操作建议 |
|------|------|---------|
| `hold` | `hold_score >= HOLD_SCORE_HIGH(70)` 且未跌破 ATR 止损 | 持有，不加仓 |
| `reduce` | `HOLD_SCORE_MED(40) <= hold_score < 70` 或 hold_score < 70 | 减仓（趋势减弱） |
| `exit` | `atr_stop_broken = True` | 立即离场（最优先） |

> hold_score 字段始终携带 0~100 整数值，上层可基于具体分值进一步细分（如 0~40 加速减仓 / 40~70 小幅减仓）。状态字段 `hold_state` 是规则的最终结论。

#### 4.10.4 与操作矩阵的边界

持有层 **不进总分、不改 action_with/action_without**（操作矩阵由象限 + 大盘 + 波动率 + 超卖反弹 + 改善信号决定）。持有层独立输出 `hold_score` / `hold_state` 字段，供已持仓者参考：
- 持有层说"持有"，但操作矩阵说"减仓" → 以操作矩阵为准（风控优先）
- 持有层说"离场" → 强制执行（移动止损是机械规则）
- 持有层说"减仓" + 操作矩阵说"清仓" → 以操作矩阵为准

#### 4.10.5 输出字段（注入 score_5d）

```
hold_score: 0~100
hold_state: 'hold' / 'reduce' / 'exit'
long_adx: float|None               # 长周期 ADX 数值
long_adx_rising: bool              # 长周期 ADX 斜率是否向上
long_rs: float|None                # 长周期 RS-Ratio
above_ma60: bool
above_ma120: bool
atr_stop_broken: bool
stop_line: float|None             # 止损线值（参考）
hold_note: str                     # 人类可读说明
```

报告表新增"持有"列，格式 `<hold_score><hold_state 中文>`，如 `75持有` / `33减仓` / `0离场`。

配置项：`HOLD_ADX_LONG_PERIOD=56` / `HOLD_ADX_THRESHOLD=20.0` / `HOLD_ADX_SLOPE_PERIOD=5` / `HOLD_RS_LONG_PERIOD=60` / `HOLD_RS_STRONG=1.0` / `HOLD_MA_LONG=60` / `HOLD_MA_LONGER=120` / `HOLD_ATR_STOP_PERIOD=14` / `HOLD_ATR_STOP_MULT=2.0` / `HOLD_SCORE_HIGH=70` / `HOLD_SCORE_MED=40`。

## 九、缓存与离线降级

### 9.1 双层缓存（`@cached` 装饰器）

- **历史层**：`{key}_history.csv` → >30 天前数据，永久缓存，不触网

- **当日层**：`{key}_latest.csv` → ≤30 天数据，TTL 20h（`CACHE_TTL_HOURS=20`）

- **合并**：history + latest 按 date 去重，keep=last

- **freshness\_check（默认开启）**：即使 TTL 未过期，若 `缓存最新日 < 今日` 也视为过期强制重拉（解决"数据源更新前拉取到旧数据并写入缓存"问题）；`min_refetch_minutes=10` 防止连续运行频繁触网

- **缓存目录**：`trading_lab/data/cache/`（相对项目根）

### 9.2 离线 / 拉取失败降级

拉取失败时优先用旧 latest 兜底（仅缺最新日）→ 仍失败用仅历史缓存 → 仍失败返回 None，对应信号标记灰灯 `data_sufficient=False`。整体流程永不因单源失败阻断。
