# 市场状态分层与入场条件适配 — 设计稿

> 结论先行：当前系统**没有真正的市场状态判别层**。它有 10 个 profile（人工预选的"场景包"）和 1 个二值大盘过滤（指数 ≥ MA20），
> 但**没有任何一处代码在运行时回答"现在是什么市"**。
> 结果：入场条件与市场状态**同源、固定、方向盲**——趋势市里被挡死，下跌市里被放行。

---

## 一、现状诊断（每条都有代码位置 + 实测证据）

### 1.1 诊断总表

| # | 问题 | 位置 | 后果 |
|---|------|------|------|
| 1 | 无 regime 判定层，靠人工选 profile | `config.py:247-258` | 用户在牛市里用 `conservative`、在震荡市里用 `trend` 都不会被拦 |
| 2 | 维度 B 把"顺势信号"与"逆势信号"用 `or` 连接 | `main.py:541-616` | 趋势市被 `RSI超买` 挡死；下跌市被 `RSI超卖` 放行 |
| 3 | 维度 C 的盈亏比**方向盲** | `main.py:641-716` | 上涨市 RR=0.36 不通过，下跌市 RR=21.8 通过 |
| 4 | 大盘过滤只看"昨日单日涨跌幅" | `market_filter.py:358-387` | −0.51% 否决，+3% 通过，连跌 5 天不否决 |
| 5 | 维度 A 回踩阈值账户级固定，非状态相关 | `config.py:27` | 趋势市几乎永不触发；震荡市可能误判"均线附近横盘"为回踩 |
| 6 | 维度 D 评级 B 把两种相反状态合并 | `weekly_observer.py:546-576` | 「多头回踩」与「空头反抽」共用一句建议，等于没判 |

### 1.2 实测证据（本次运行）

### 1.3 三条可复现的"反常识"点

**(a) 上涨市不通过，下跌市通过 —— 维度C 方向盲**

`_calc_stop_price` 的 `swing` 用「近 20 日最低」、`_calc_profit_price` 的 `swing_enhanced` 用「近 20 日最高」。
上涨趋势中 20 日低点远离现价 → `loss_space` 巨大 → RR=0.36 被判不合格；
下跌趋势中 20 日低点贴近现价 → `loss_space` 极小 → RR=21.8 轻松通过。
**它系统性地奖励"跌到 20 日低点附近"，惩罚"涨到 20 日高点附近"**——这与"趋势跟随"完全相反。

**(b) 大盘 −0.51% 否决，+3% 通过 —— 单日阈值的不对称**

`market_filter.py:361-387` 只用 `(cur/prev − 1)` 与 `BENCHMARK_MIN_CHANGE_PCT` 比较：

```
  今日 +3.00% → passed=True
  今日 +0.10% → passed=True
  今日 -0.40% → passed=True
  今日 -0.51% → passed=False   ← 一根小阴线即否决
  今日 -0.60% → passed=False
```

而"连跌 5 天每天 −0.3%（累计 −1.5%）"却会**全部通过**（每天都 ≥ −0.5%）。
真正的风险是趋势性阴跌，代码却只在防单日暴跌——而且防的是最不该防的那 0.01%。

**(c) 下跌放量被当成买入信号**

维度 B 的 `vol_surge` 只比较"当前量 > 5 日均量 × 1.5"，**不看这根量是阴量还是阳量**。
缩量阴跌样本里 `成交量放大 (1.9倍)` 直接让 B 通过——放量破位被读成了"真金白银进场"。

**(d) 回踩判定的语义混淆**

`main.py:372-399` 的第 ⑤ 步是「最近 N 根内**是否贴近均线**」，
它无法区分「从上方回踩到均线」（想要的买点）和「贴着均线横盘」（无信号的整理）。
再加上前 4 条的 AND 叠加（偏离 ≤0.5% + 均线向上 + 缩量 + 阳线/锤子线），
实测通过率约 5%，**维度 A 实际更像一个"永远说不"的过滤器**，而不是买点识别器。

## 二、根因：入场条件与市场状态"同源"

一个健康的系统应当是 **regime → 策略 → 阈值** 三层：

```
① 市场状态（客观事实）   现在是什么市？       ← 当前系统完全缺失
② 该状态下的策略        该做什么方向？       ← 当前是人工选 profile（1.1 表 #1）
③ 该策略的参数阈值      具体多少算合格？     ← 当前是 config.py 全局固定值（1.1 表 #5）
```

当前系统只有 ②③ 且**与 ① 无连接**：`RSI_OVERSOLD=30` 在趋势市和震荡市里是同一个 30；
`MIN_RR_RATIO=2.0` 在上涨市和下跌市里是同一个 2.0。于是出现 1.3(a) 那种"机器给出与行情相反结论"。

## 三、改造方案

### 3.1 第一步：新增 `regime_detector.py`（只读模块，与 A/B/C/D 解耦）

输入=基准指数日线（复用 `market_filter._fetch_index`），输出=一个 regime dict。
**只做分类，不做否决**——先让它跑一周跟人工判断对账，再谈接入判定。

判定事实（全部可在 120 根日线上算出，无未来函数）：

| 事实 | 计算 | 用途 |
|------|------|------|
| 均线排列 | MA5/MA20/MA60 的上下顺序 + MA20 斜率（近 5 根） | 区分趋势 / 震荡 |
| ADX(14) | 标准 Wilder ADX | **专治震荡市**：ADX<20 无趋势 |
| 波动率分位 | 当前 ATR(14) 在过去 120 日 ATR 中的分位数 | 区分常态 / 高波动 / 恐慌 |
| 布林带宽 | (上轨−下轨)/中轨，20 日 2σ | 区分收敛 / 扩张 |
| 区间高度比 | 近 20 日振幅 / 近 20 日均 ATR | 横盘就是"高度≈1 倍 ATR" |
| 位置 | 收盘距 MA60 的百分比 | 高位 / 低位 |

### 3.2 七态判定规则（可直接实现）

| 状态 | 判定（AND） | 一句话含义 |
|------|-------------|-----------|
| `PANIC_DOWN` 恐慌急跌 | ATR分位 > 0.9 **且** 指数 < MA20 **且** 近 3 日累计 < −3% | 泥沙俱下，唯一任务是别接刀 |
| `TREND_UP` 趋势上涨 | MA5>MA20>MA60 **且** MA20 斜率 > 0 **且** ADX≥25 **且** 收盘 > MA60 | 单边，回调即机会 |
| `TREND_DOWN` 趋势下跌 | MA5<MA20<MA60 **且** MA20 斜率 < 0 **且** ADX≥25 **且** 收盘 < MA60 | 反弹是逃命，不是买点 |
| `RANGE_HIGH` 高位震荡 | ADX<20 **且** 收盘距 MA60 > +8% **且** 带宽在收窄 | 顶部区，突破多为诱多 |
| `RANGE_LOW` 低位震荡 | ADX<20 **且** 收盘距 MA60 < −8% | 底部区，适合区间低吸 |
| `RANGE_MID` 中位震荡 | ADX<20 **且** 其余情况 | 标准箱体，高抛低吸 |
| `SQUEEZE` 极缩量横盘 | 带宽 < 近 120 日 10% 分位 | 变盘前夜，等方向，不猜 |

优先级：`PANIC_DOWN` → `TREND_*` → `SQUEEZE` → `RANGE_*`（先判最极端，再兜底震荡）。

### 3.3 第二步：由 regime 决定"允许哪类入场条件"

这是回答"是否判断了市场特点、并据此选入场条件"的核心表。

| 状态 | 主用维度 | 关键信号 | 明确**禁止** | 止损 / 止盈模式 |
|------|----------|----------|--------------|-----------------|
| `TREND_UP` | A 用**突破/回踩浅**（不等 0.5% 贴近），B 用 **MACD 金叉 | 柱线翻红** | **忽略 `RSI超买`**；忽略"突破必须放量"（趋势中缩量创新高是常态） | `STOP_MODE=atr`（1.5） / `PROFIT_MODE=atr` 追踪 |
| `TREND_DOWN` | **B 只允许做超卖反弹且必须 AND 放量阳线 + J值/RSI 极值 + 前低支撑**；A 用"回踩不破"而非"贴线" | 超卖 + 缩量止跌 + 站回 MA5 | **禁止纯 RSI 超卖**；禁止"突破"信号（下跌趋势中的突破=诱多） | 紧止损 1.0×ATR，目标=反抽 MA20 即走 |
| `RANGE_MID` / `RANGE_LOW` | **主用均值回归**：价格触及 布林下轨 / 箱体下沿 / MA20 | RSI<30 **且** 缩量 **且** 下轨支撑 三者 **AND** | **禁止突破买入**（区间上沿的突破假信号率最高） | `STOP_MODE=swing` 用箱体下沿外 1×ATR / `PROFIT_MODE=swing` 用箱体上沿 |
| `RANGE_HIGH` | 只减不增；个股入场需"缩量回踩不破 + 周线评级 A" | 同上 + 周线 D 评级必须为 A | 禁止追高、禁止"突破新高" | 止损上移（ATR×1.0），止盈保守 |
| `SQUEEZE` | 只观察，不下手（或极小仓试单） | 等带宽扩张方向确认后再按新 regime 处理 | 禁止任何方向性入场 | — |
| `PANIC_DOWN` | 空仓 | — | 全部禁止 | — |

### 3.4 第三步：阈值随 regime 缩放（示例）

```python
REGIME_THRESHOLDS = {
    "TREND_UP":   {"PULLBACK_MAX_DEVIATION": 0.020,   # 0.5% → 2.0%：趋势中回调不会贴到均线
                   "MIN_RR_RATIO": 1.8,
                   "ALLOW_BREAKOUT": True,
                   "IGNORE_RSI_OVERBOUGHT": True,
                   "STOP_MODE": "atr", "PROFIT_MODE": "atr"},

    "RANGE_MID":  {"PULLBACK_MAX_DEVIATION": 0.005,   # 收紧：只有精准触下沿才算
                   "MIN_RR_RATIO": 2.5,
                   "ALLOW_BREAKOUT": False,           # 震荡市禁突破
                   "REQUIRE_RSI_OVERSOLD": True,
                   "STOP_MODE": "swing", "PROFIT_MODE": "swing"},

    "TREND_DOWN": {"MIN_RR_RATIO": 3.0,               # 逆势要求更高赔率
                   "ALLOW_BREAKOUT": False,
                   "REQUIRE_RSI_OVERSOLD": True,
                   "REQUIRE_BULLISH_VOLUME": True,    # 放量必须是阳量
                   "STOP_MODE": "atr", "PROFIT_MODE": "swing_ultra"},
}
```

接入点极干净——`main.py:1161` 拿到 config 之后、跑三维度之前插一段：

```python
regime = detect_regime(config)                       # 只读，失败不影响主流程
config = apply_regime_overrides(config, regime)      # 用上面的表覆盖阈值
print_regime_block(regime)                           # 输出一个独立的【维度E - 市场状态】区块
```

**注意方向性**：这套改造必须与你现在"维度 D 只读、不否决"的哲学一致——
建议 regime 也一样：**先把结论打印出来让人看，跑一段对账期后再让它自动改阈值**。
不要一上来就用它一票否决，否则你只是把"固定阈值"换成了"固定分类器的错误"。

## 四、回测验证（最重要的一步，当前完全缺失）

没有这一步，上述所有阈值调整都只是"换一套拍脑袋"。做法：

1. 取 200 只票 × 5 年日线，**在每个历史 bar 上重算 regime**（严格只用当日及之前数据）。
2. 记录每个信号 `(regime, 维度A通过, 维度B通过, 维度C通过)` 的：
   - 未来 5/10/20 日收益分布
   - 最大有利波动 MFE / 最大不利波动 MAE
   - **是否先触发止损**（这个比收益更能说明问题）
3. 按 regime 分层出表：

| regime | 信号数 | 胜率 | 平均盈亏比 | 先触止损率 | 期望值 |
|--------|--------|------|-----------|-----------|--------|
| TREND_UP + 回踩 | ? | ? | ? | ? | ? |
| RANGE_MID + 下轨 | ? | ? | ? | ? | ? |
| TREND_DOWN + RSI超卖 | ? | ? | ? | ? | ? |

`TREND_DOWN + RSI超卖` 这一行大概率会是负期望——那正是当前系统在实盘中会放行的组合。
用数据证明它，然后把 `ALLOW_RSI_OVERSOLD_ALONE = False` 写死，才算真正"根据市场情况判断入场条件"。

## 五、最小改动清单（若不想大改）

按性价比排序，前两条就能堵住最严重的漏洞：

1. **维度 B 拆成两组信号并加 regime 开关**（`main.py:520-638`）
   - `TREND_UP` → 只看 `MACD金叉 | MACD柱线翻红 | 放量阳线`
   - `RANGE_*` / `TREND_DOWN` → 只看 `RSI超卖 + 缩量止跌`，且**要求 AND 而非 OR**
2. **修掉 `market_filter` 的单日阈值**（`market_filter.py:358-387`）
   - 补一个"近 5 日累计涨跌幅"条件（防连跌阴跌）
   - 把"单日大跌"从 −0.5% 放宽到 −1.5%（单日 `RSI超买` 不管，单日大跌才是真风险）
   - 或直接换成"指数 ATR 分位 > 0.9 才拦"
3. **维度 C 加方向约束**（`main.py:656-682`）
   - `swing` 止损改为止损位 `max(20日低点, 现价 − 2×ATR)`（避免涨势中止损过远）
   - 或按 regime 切换 `STOP_MODE`（趋势 → atr，震荡 → swing）
4. **维度 D 评级 B 拆成 B1/B2**（`weekly_observer.py:546-576`）
   - B1 多头回踩：MA20 向上 但价格在 MA20 下 → "回踩中，等日线止跌"
   - B2 空头反抽：MA20 向下 但价格在 MA20 上 → "反抽中，不追"
   - 并把 `facts` 里的 `macd_hist` 纳入评级（现在算了却完全没参与评级）
5. **先做回测脚本**，再动阈值。

## 六、附：本次用到的复现脚本

```python
# 生成合成行情并调用三维度（无网络依赖）
import sys; sys.path.insert(0, '.')
import numpy as np, pandas as pd
from config import TradingConfig
import main as M

def mk(n=160, drift=0.0, amp=0.0, vol=0.015, seed=1):
    rng = np.random.default_rng(seed)
    close = 10*np.exp(np.cumsum(rng.normal(drift, vol, n)))
    if amp: close = close + amp*np.sin(np.arange(n)/10)
    op = np.r_[close[0], close[:-1]]
    hi, lo = np.maximum(op, close), np.minimum(op, close)
    return pd.DataFrame({"date": pd.bdate_range("2024-01-01", periods=n),
                         "open": op, "high": hi, "low": lo, "close": close,
                         "volume": rng.lognormal(0, .4, n)*1e6})

cfg = TradingConfig()
print(M.check_dimension_b(mk(drift=0.006, seed=2), cfg))   # 强势上涨
print(M.check_dimension_b(mk(drift=-0.006, seed=3), cfg))  # 强势下跌
```

注：上述合成数据的绝对通过率不能替代真实回测（真实个股有跳空与波动聚集），
但足以证明**信号与市场状态之间没有正确的条件依赖关系**。
