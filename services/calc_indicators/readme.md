# 开仓前三维度快速筛查工具

输入股票代码，从 **结构 / 动量 / 赔率** 三个维度判断是否值得开仓。

## 快速开始

```bash
# 默认配置筛查 600118
python main.py 600118

# 指定单个配置档
python main.py 600118 -p high_vol
python main.py 600118 -p aggressive_short

# 叠加多个配置档（后者覆盖前者「显式声明」的字段）
python main.py 600550 -p aggressive_short -p long_term --show-config

# 单字段精确覆盖（类型安全）
python main.py 600550 -o ENABLE_MARKET_FILTER=false -o MIN_RR_RATIO=1.5

# 组合使用：叠加 + override + 详细日志
python main.py 600550 -p aggressive_short -p long_term \
                     -o PULLBACK_MAX_DEVIATION=0.008 \
                     -v --show-config

# 生成可视化 PNG 报告（K线+成交量+MACD+RSI+止损止盈+总结）
python main.py 600550 -p aggressive_short -r

# 生成报告并自动用浏览器打开
python main.py 600550 -p aggressive_short -r --open

# 查看所有配置档与帮助
python main.py --help
```

## 命令参数

| 参数                  | 说明                                       |
| ------------------- | ---------------------------------------- |
| `<股票代码>`            | 必填，6 位 A 股代码，如 `600118`                  |
| `--profile` / `-p`  | 可选，配置档名称，**可重复传入以叠加**，默认 `default`       |
| `--override` / `-o` | 可选，单字段覆盖 `KEY=VALUE`，**可重复**，类型安全解析      |
| `--verbose` / `-v`  | 可选，启用详细日志（输出 `logger.info` 的排查过程）        |
| `--show-config`     | 可选，运行前打印当前生效的 TradingConfig 全量字段 + 来源    |
| `--report` / `-r`   | 可选，生成可视化 PNG 报告（K线+成交量+MACD+RSI+止损止盈+总结） |
| `--open`            | 可选，配合 `--report` 使用，生成后自动用浏览器打开图片        |
| `--compare` / `-c`  | 可选，对比模式：指定第二只股票代码，两只股票三维度对比 + 对比图 + 结论   |
| `--no-weekly`       | 可选，跳过维度D（周线趋势背景观察哨）的显示，A/B/C 仍正常运行       |
| `--no-regime`       | 可选，跳过维度E（市场状态雷达）的显示，A/B/C/D 仍正常运行        |
| `--etf`             | 可选，ETF 模式：基准指数切到该 ETF 的**标的指数**，并下调 ETF 放量门槛 |
| `--auto-etf`        | 可选，按代码前缀自动识别 ETF 并进入 ETF 模式（`51x/56x/58x/159` 等） |
| `--index`           | 可选，基准指数：填代码（如 `sz399006`）或 `auto`（按相关性自动选） |
| `--help` / `-h`     | 查看帮助                                     |

## 配置档一览（10 个预设）

| 配置档                | 类名                    | 适用场景                  | 特点                           |
| ------------------ | --------------------- | --------------------- | ---------------------------- |
| `default`          | TradingConfig         | 标准配置 - 日常使用           | swing\_enhanced 止盈，短线回踩增强已启用 |
| `high_vol`         | HighVolatilityConfig  | 高波动配置 - 急跌反弹行情        | ATR 止损，放宽容忍度，轻仓试错            |
| `conservative`     | ConservativeConfig    | 保守配置 - 震荡市/不确定行情      | 严格筛选，2.5:1 盈亏比，极轻仓           |
| `trend`            | TrendFollowingConfig  | 趋势跟随配置 - 单边行情         | swing 止损 + ATR 止盈，让利润奔跑      |
| `aggressive_short` | AggressiveShortConfig | 激进短线 - 精准踩 MA5        | 0.3% 极严偏离，允许均线走平             |
| `steady_short`     | SteadyShortConfig     | 稳健短线 - MA5/MA10 双均线确认 | 0.8% 偏离，要求趋势向上               |
| `short_term`       | ShortTermConfig       | 超短线 - 强制大盘过滤          | 大盘 MA20 + 单日跌幅 ≤ -0.5%       |
| `ultra_short`      | UltraShortConfig      | 超短线止盈止损 - 紧止损+10日高压基准 | 入场-1×ATR 止损，10日最高+2×ATR 止盈   |
| `swing`            | SwingConfig           | 波段 - 放宽大盘涨跌幅限制        | 大盘 MA20 + 单日跌幅 ≤ -1.0%       |
| `long_term`        | LongTermConfig        | 长线价投 - 关闭大盘过滤         | 看内在价值，跌了反而便宜                 |

### 按维度分类

- **维度 A（结构/回踩）**：`aggressive_short` / `steady_short`

- **维度 B（动量/大盘）**：`short_term` / `swing` / `long_term`

- **维度 C（赔率/止损止盈）**：`high_vol` / `conservative` / `trend` / `ultra_short`

## 多 profile 叠加（重点功能）

不同 profile 通常只改自己负责的维度，**互不冲突，可以叠加**。

### 叠加规则

1. 第一个 profile 作为基底
2. 后续每个 profile **仅覆盖它自己在类里"显式声明"的字段**（`class.__dict__` 中直接出现的）
3. 从父类继承来的默认值**不参与覆盖** —— 避免误覆盖

### 常见叠加组合

```bash
# 激进短线（维度A） + 关闭大盘过滤（维度B）
python main.py 600550 -p aggressive_short -p long_term

# 稳健短线（维度A） + 波段大盘过滤（维度B）
python main.py 600550 -p steady_short -p swing

# 稳健短线（维度A） + 波段大盘（维度B） + 高波动止损（维度C）
python main.py 600550 -p steady_short -p swing -p high_vol --show-config
```

## 单字段覆盖 `--override` / `-o`

无需改 config.py，直接命令行精确改一个字段，**类型安全解析**。

### 支持的类型

| 字段类型       | 语法示例                                        | 说明                           |
| ---------- | ------------------------------------------- | ---------------------------- |
| `bool`     | `true` / `false` / `1` / `0` / `yes` / `no` | 大小写不敏感                       |
| `int`      | `20` / `0x14` / `0b10100`                   | 支持 0x / 0b 前缀                |
| `float`    | `0.01` / `1.5` / `500000`                   | 十进制浮点                        |
| `List[T]`  | `[5,10]` 或 `5,10`                           | 按 T 自动解析（int/float/str/bool） |
| `Tuple[T]` | `[5,10,20,60]` 或 `5,10,20,60`               | 同上，结果为 tuple                 |
| `str`      | `swing` / `'atr'`                           | 原样，引号自动脱除                    |

### 实战示例

```bash
# 只关大盘过滤，其他全 default
python main.py 600550 -o ENABLE_MARKET_FILTER=false

# 调整盈亏比门槛 + 资金规模
python main.py 600550 -o MIN_RR_RATIO=1.5 -o TOTAL_CAPITAL=500000

# 切换止损模式 + 调整 ATR 倍数
python main.py 600550 -o STOP_MODE=atr -o ATR_STOP_MULT=2.0

# 改回踩目标均线（zsh 下含 [] 需加引号，bash 不需要）
python main.py 600550 -o 'PULLBACK_MA_TARGETS=[5,10]' -o PULLBACK_MAX_DEVIATION=0.008

# 与 profile 叠加使用
python main.py 600550 -p aggressive_short -p long_term \
                     -o PULLBACK_MAX_DEVIATION=0.008 -v --show-config
```

### 错误提示

- `-o UNKNOWN_KEY=xxx` → 列出全部 39 个可用字段

- `-o just_a_string`（无等号）→ 提示 "应为 KEY=VALUE 格式"

- 类型不匹配 → `ValueError` 带明确信息

## 入口门控（打通「市场状态 / RSI超买 / 赔率」三否决）

**这是当前最该先看的一节。** 背景是一个真实案例（002119，2026-09-24）：

```
维度A ✅ 突破前20日高点 26.92      ← 现价 29.61，突破幅度 +9.99%，已属追高
维度B ✅ 信号: RSI超买 (84.5), 成交量放大 (2.0倍)
维度C ❌ 止损 21.69(−26.7%) 止盈 32.29(+9.1%) → 盈亏比 0.34:1
维度D   周线评级 A，但价格距周 MA60 +37.1%
维度E   RANGE_MID，备注"禁止突破买入" —— 却只读不参与判定
```

系统明知市场不支持突破，仍让 A/B 通过。**门控层就是补这个洞。**

### 设计：维度与风控分离

| 层 | 回答的问题 | 代码 |
| --- | --- | --- |
| 维度 A/B/C | 信号**成不成立** | `check_dimension_a/b/c`（返回契约不变） |
| **入口门控** | 这笔**能不能做** | `check_entry_gate()` |

为什么单开一层而不是改 A/B/C：那三个函数的返回契约被 `backtest.py` 与 6 个验证脚本
共 20 余处依赖，改语义会连坐整条测试链，也会把"信号判定"与"风控否决"混为一谈。

### 三条规则（各自可独立关闭）

| 规则 | 条件 | 开关（默认） |
| --- | --- | --- |
| `REGIME_BREAKOUT` | 市场状态不在白名单 **且** 当前处于刚突破前高的状态 | `ENTRY_GATE_REGIME_ENABLED=True` |
| `RSI_EXTREME` | 日线 RSI ≥ `MOMENTUM_RSI_EXTREME`（80） | `ENTRY_GATE_RSI_ENABLED=True` |
| `RR_RATIO` | C 未通过（盈亏比 < `MIN_RR_RATIO`） | 复用 C 判定，仅做归因 |

- 白名单：`ENTRY_GATE_BREAKOUT_ALLOWED_REGIMES = ["TREND_UP", "SQUEEZE"]`，其余状态禁突破
- 规则**只针对突破入场**；回踩入场不受 `REGIME_BREAKOUT` 约束
- 判"是不是突破"时会**独立复算**突破事实，不只看 A 是否通过 ——
  否则 A 因幅度过大被拦时，该规则会自我豁免，少一道防线

### 输出示例

```
【入口门控 - 市场状态 / RSI超买 / 赔率】
  🚫 REGIME_BREAKOUT: 市场状态 RANGE_MID（中位震荡）不允许突破买入，而当前处于刚突破前高的状态
  🚫 RSI_EXTREME: 日线 RSI 84.5 ≥ 极端超买线 80（突破追高中的情绪顶风险）
  🚫 RR_RATIO: 盈亏比 1.13:1 < 2.0:1（该赔率需胜率 > 46.9% 才不亏）
  ⇒ 被 3 条风控否决

【仓位建议】
  🚫 不适用 —— 维度 A/C 未通过；风控否决 REGIME_BREAKOUT/RSI_EXTREME/RR_RATIO
     （C 口径下的参考仓位为 100 股，仅供参考，不建议按此下单）

============================================================
❌ 暂不建议开仓 —— 维度 A/C 未通过；风控否决 3 项
     · 市场状态 RANGE_MID（中位震荡）不允许突破买入，而当前处于刚突破前高的状态
     · 日线 RSI 84.5 ≥ 极端超买线 80（突破追高中的情绪顶风险）
     · 盈亏比 1.13:1 < 2.0:1（该赔率需胜率 > 46.9% 才不亏）
============================================================
```

### 边界处理（都很关键）

| 场景 | 行为 |
| --- | --- |
| 市场状态取数失败 | **跳过** `REGIME_BREAKOUT` 并在输出标注"本规则已跳过" —— 不因失败而放行，也不因失败而误拦 |
| RSI 为 NaN | 跳过该规则（NaN 比较为 False，不会误否决） |
| 三项全关 / 总开关关 | 完全回到"仅看 A/B/C" |
| 对比模式 | 门控按各自标的分别计算；对比结论**先看风控否决数**（否决少者胜出） |

### 门控配置字段

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `ENTRY_GATE_ENABLED` | `True` | 门控总开关 |
| `ENTRY_GATE_REGIME_ENABLED` | `True` | 震荡市禁突破 |
| `ENTRY_GATE_RSI_ENABLED` | `True` | RSI 极端超买否决 |
| `ENTRY_GATE_BREAKOUT_ALLOWED_REGIMES` | `["TREND_UP","SQUEEZE"]` | 允许突破的市场状态白名单 |
| `MOMENTUM_RSI_EXTREME` | `80.0` | 极端超买线（70 是"偏高"，80 是"极端"） |

```bash
# 关闭全部门控（回到仅看 A/B/C）
-o ENTRY_GATE_ENABLED=false

# 只关市场状态规则
-o ENTRY_GATE_REGIME_ENABLED=false
```

### 配套改动（同批落地）

| 改动 | 说明 |
| --- | --- |
| **突破质量过滤** | 新增 `BREAKOUT_REQUIRE_FRESH`(需最近3根内确认)、`BREAKOUT_MAX_PCT`(幅度≤5%)；002119 的 +9.99% 会被 A 直接拒为"追高" |
| **近端止损默认** | `STOP_MODE` 由 `swing` 改为 `near_low`（近5日低点 + 8% 距离上限）；002119 盈亏比 0.34→1.13（**仍不达 2:1**，说明单靠换止损救不了这笔） |
| **仓位显示纪律** | 只有综合通过才给股数；未通过显示"不适用 + 参考仓位（不建议照此下单）" |
| **周线背离提示** | 周线 A 但日线 RSI 极端超买、或价格距周 MA60 ≥30% → 提示日周背离与仓位折减建议 |
| **输出顺序** | 数据 → A/B/C → 门控 → 仓位 → 结论 → E → D，避免"不通过却先给出股数" |

| --- | --- | --- |

| `BREAKOUT_CONFIRM_BARS` | `3` | 新鲜度窗口 |
| `BREAKOUT_MAX_PCT` | `0.05` | 突破幅度上限；设 `None` 恢复不限制 |
| `NEAR_LOW_WINDOW` | `5` | 近端止损回看根数 |
| `NEAR_LOW_MAX_PCT` | `0.08` | 近端止损距现价上限 |
| `WEEKLY_FAR_FROM_MA60_PCT` | `30.0` | 周线"远离"阈值（触发仓位折减提示） |
| `WEEKLY_FAR_POSITION_DISCOUNT` | `0.5` | 远离时的建议仓位折扣 |

## 维度 A 回踩信号增强

默认启用 `USE_PULLBACK_ENHANCE = True`，使用短线回踩信号判定：

| 检查项    | 说明               | 默认值      |
| ------ | ---------------- | -------- |
| 回踩目标均线 | 检查哪些 MA 周期       | \[5, 10] |
| 偏离度容忍  | 收盘价距 MA 的最大偏离    | 0.5%     |
| 均线方向   | 均线必须向上翘头         | 是        |
| 缩量要求   | 成交量 < 5 日均量 × 系数 | 0.8      |
| K 线形态  | 阳线或锤子线（止跌形态）     | 是        |
| 确认窗口   | 最近 N 根 K 线内确认    | 2 根      |

**向后兼容**：设置 `USE_PULLBACK_ENHANCE = False` 回退到原 MA20 ± 1% 判定。

### 切换止损/止盈模式

通过 `-o` 或编辑 `config.py`，修改 `STOP_MODE` 和 `PROFIT_MODE`：

| 模式               | 说明                                                      |
| ---------------- | ------------------------------------------------------- |
| `swing`          | 结构派：前 20 日低点止损 / 高点止盈                                   |
| `swing_enhanced` | 增强结构派：MAX(20日最高价, 入场价 + 2×ATR) 止盈（default 默认）           |
| `swing_ultra`    | 超短线压力派：RR\_WINDOW(默认10)日最高价 + N×ATR 止盈（ultra\_short 默认） |
| `atr`            | 波动率派：现价 ± N×ATR(14)                                     |
| `fixed`          | 固定派：现价 × (1 ± 固定百分比)                                    |

## 维度 B 信号分工（RSI 降级为确认信号）

**改动依据**（P0 回测 5818 条信号实测，完整数据见 `backtest_p0_report.md` §2/§6）：

| B 信号 | 样本 | 10日均% | 胜率10 |
| --- | --- | --- | --- |
| MACD金叉 / 柱线翻红 | 802 | +0.77 | **52.6%** |
| 成交量放大 | 1304 | **+1.18** | 49.6% |
| RSI超卖（单独） | 2849 | +0.46 | **49.8%** |
| RSI超卖（有其他信号并存） | 189 | **+1.13** | **53.4%** |

⇒ **RSI 超卖本身不是买点**，它是"跌得够深"的确认信息。

### 新逻辑

| 角色 | 信号 | 作用 |
| --- | --- | --- |
| **触发** | `MACD金叉/柱线翻红` 或 `成交量放大` | 决定维度B 是否通过 |
| **确认** | `RSI超卖` | 不再单独放行；被确认时输出标注 |
| **闸门**（默认关） | `RSI超买` | 可一票否决；另有入口门控的 `RSI_EXTREME` 更严 |

顺带修掉一处重复计数：`hist=(DIF−DEA)×2` ⇒ **"柱线翻红"与"金叉"数学恒等**
（实测样本数完全相同：802 vs 802），原"四信号 OR"实为三个独立信号。

### ⚠️ 重要：这个改动**没有统计显著的正收益证据**

改完后均值从 +0.71% 升到 +1.07%、胜率 50.3%→51.1%，但：

```
逐只对照：更差 16 只 / 更好 15 只          ← 基本对半
Bootstrap 2000 次，差值 95% 区间 = [-0.085%, +0.809%]   ← 含 0
```

推导依据时犯了**选择偏差**：拿"RSI 需确认"这个**子集**去和**全体**比，
而子集本身是按条件挑出来的，表现更好不能证明该条件有预测力。

**保留这个改动的理由是"逻辑正确"，不是"收益更高"**：
① RSI 超卖不构成买点；② 消除了 `A✅B✅` 那批急跌接刀（MAE 中位 −5.78%，最差）；
③ 修掉重复计数。**代价是信号减少 60%**（4783 → 1934）。

### 配置字段

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `MOMENTUM_RSI_REQUIRE_CONFIRM` | `True` | RSI超卖需 MACD/放量确认才计入通过（False=旧行为） |
| `MOMENTUM_RSI_VETO_OVERBOUGHT` | `False` | RSI超买时一票否决维度B |
| `MOMENTUM_RSI_COUNTS_AS_SIGNAL` | `True` | RSI 是否仍计入"维度通过数/对比评分"（向后兼容） |
| `MOMENTUM_RSI_EXTREME` | `80.0` | 极端超买线（供入口门控的 `RSI_EXTREME` 使用） |

```bash
# 回退到旧行为
-o MOMENTUM_RSI_REQUIRE_CONFIRM=false
# 自检（含 bootstrap 显著性检验）
uv run python services/calc_indicators/verify_momentum_roles.py
```

## 维度 B 大盘环境过滤

启用后会在检查个股动量之前，先看大盘指数（默认上证综指 `sh000001`）是否安全。

### 判定流程

1. **趋势判定**：指数收盘价必须站上 MA20
2. **当日涨跌幅**：必须 ≥ 阈值（`short_term` = -0.5%，`swing` = -1.0%）

### 风格对照

| 风格   | 配置档          |  大盘过滤  | 涨跌幅阈值 | 理由             |
| ---- | ------------ | :----: | :---: | -------------- |
| 超短线  | `short_term` | ✅ 强制开启 | -0.5% | 吃情绪溢价，大盘暴跌泥沙俱下 |
| 波段   | `swing`      |  ✅ 开启  | -1.0% | 可忍受短期回调，但防股灾   |
| 长线价投 | `long_term`  |  ❌ 关闭  |  不适用  | 看内在价值，跌了反而便宜   |

## 维度 D - 周线趋势背景（独立观察哨）

**模块性质**：独立的信息面板（**只读模式**），不参与 A/B/C 维度的总分计算，
**不触发自动止损或自动开仓**。维度D 只负责从周线数据接口取数 + 计算 + 显示。

### 耦合设计（与 A/B/C 完全解耦）

| 解耦层     | 设计                                                                                                                                 |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **数据层** | 独立调用周线数据接口（efinance klt=102 周线优先，baostock frequency='w' 兜底），与日线 DataFrame 完全隔离。周线获取失败（网络超时/接口报错）时，仅输出"周线数据暂不可用"，**绝不影响 A/B/C 的运行** |
| **逻辑层** | 不修改 A/B/C 任何函数内部逻辑，仅在最终输出层新增一个独立的区块，所有日志带 `[D-周线观察]` 前缀（emoji：🛰️），与 A/B/C 的 ✅ ❌ 严格区分                                              |
| **缓存层** | 周线数据日内不变，每天只计算 1 次（首次调用时），结果按 `(symbol, 日期)` 写入进程内缓存，日内复用避免被禁 IP                                                                   |

### 5 项硬指标

拉取最近 120 根周 K 线，计算以下 5 项底层事实供人工查阅：

|  序号 | 检查项          | 计算规则                                   | 输出示例                                     |
| :-: | ------------ | -------------------------------------- | ---------------------------------------- |
|  ①  | 周线 MA20 趋势   | 对比本周 MA20 vs 上周 MA20（变化幅度 < 0.1% 视为走平） | `向上` / `走平` / `向下`                       |
|  ②  | 价格与周 MA20 关系 | 当前最新收盘价是否站上 MA20                       | `站上（多头区域）` / `跌破（空头区域）`                  |
|  ③  | 周线 MA60（牛熊线） | 当前价格与 MA60 的距离百分比                      | `价格距周MA60：+5.2%（上方）` / `-3.1%（下方）`       |
|  ④  | 周线 RSI(14)   | 计算周线级别 RSI，判断极端情绪                      | `当前值：42.5（中性）` / `超卖区（<30）` / `超买区（>70）` |
|  ⑤  | 周线 MACD 柱状体  | 判断绿柱是否在缩短（止跌）或红柱是否在缩短（滞涨）              | `绿柱连续缩短（第3根）` / `红柱缩短（顶背离隐患）`            |

### 周线综合评级（不带自动否决权）

基于 5 项事实自动给出综合评级，**仅供人工参考**，不影响 A/B/C 的通过判定：

|   评级  | 名称      | 触发条件                                  | 给人工的建议                             |
| :---: | ------- | ------------------------------------- | ---------------------------------- |
| **A** | 多头趋势良好  | MA20 向上 + 价格站上 MA20 + RSI ∈ \[40, 60] | 周线顺风，日线买点可信度高，可考虑正常仓位介入            |
| **B** | 震荡/方向不明 | 其他情况（MA20 走平 / 价格缠绕 / 极端 RSI / 反抽中等）  | 周线无明确方向，建议降低仓位，严格按日线止损执行           |
| **C** | 空头趋势压制  | MA20 向下 且 价格在 MA20 之下                 | 周线逆风，当前日线超卖仅为反弹，强烈建议放弃入场，或仅用极小仓位试盘 |

> 评级优先级：先判 C（空头最严）→ 再判 A（多头需三条件齐备）→ 剩余归 B（震荡兜底）。
> 这样保证"多头需温和健康（RSI 不超买不超卖）才能评 A，否则归 B"。

## 信息流向与人工决策对照表

### 信息流向

```
程序自动算  →  输出 维度A结果、维度B结果、维度C结果、维度D评级（纯周线）

你人工来看  →  把 日线信号（A+B+C） 和 周线背景（D评级） 摆在眼前，按下表做最终拍板
```

> 维度A/B/C 是日线级别的开仓信号判定（结构/动量/赔率），维度D 是周线级别的趋势背景判定。
> 程序**不会**用维度D 去否决 A/B/C，也不会自动开仓/止损——维度D 只是把周线事实摆在眼前，
> 由人工根据"日线信号 + 周线背景"的组合做最终拍板。

### 人工决策对照表

| 日线信号（A+B+C 的结果） | 周线背景（维度D 评级） | 你的人工决策（拍脑袋）         |
| --------------- | :----------: | ------------------- |
| 日线超卖反弹（B 通过）    | D 评级 = A（多头） | **顺大势，逆小势** → 开仓    |
| 日线超卖反弹（B 通过）    | D 评级 = C（空头） | **逆大势，逆小势** → 放弃    |
| 日线回踩企稳（A 通过）    | D 评级 = C（空头） | **火中取栗** → 放弃或轻仓    |
| 日线无信号（A/B 全挂）   | D 评级 = A（多头） | **等回调到位再进** → 继续空仓等 |

### 决策逻辑解读

- **顺大势，逆小势**：周线多头（大势顺风）下的日线超卖反弹（小势逆势：跌中反弹）是较佳买点。
  周线大方向向上提供安全垫，日线超卖提供买点，胜率较高 → 开仓。

- **逆大势，逆小势**：周线空头（大势逆风）下的日线超卖反弹大概率是下跌中继的反弹，
  抢反弹风险大，盈亏比不佳 → 放弃。

- **火中取栗**：周线空头下的日线回踩企稳可能只是下跌中继的暂时企稳，
  看似回踩到位实则可能继续破位 → 放弃或仅极小仓位试盘。

- **等回调到位再进**：周线多头说明大方向好，但日线无买点说明当前不是入场时机。
  应等日线出现回调买点再进，而不是追高 → 继续空仓等。

## 维度 E - 市场状态雷达（regime detector）

**定位**：7 态市场状态分类器。它现在是**入口门控的输入之一**（见「入口门控」），
但仍保持"不修改 A/B/C 判定"的契约 —— 门控只读它的结论。

### 7 种市场状态

| 状态 | 中文 | 判定要点 | 该状态的入场倾向 |
| --- | --- | --- | --- |
| `PANIC_DOWN` | 恐慌急跌 | 波动率高位+近3日大跌+跌破MA60，或近3日跌幅 ≤ -2.5×ATR% 且跌破 MA20/MA5 | 空仓 |
| `TREND_UP` | 趋势上涨 | MA5>MA20>MA60 + MA20上行 + ADX≥25 + 未反复穿越中轨 + 站上MA60 | **允许突破** |
| `TREND_DOWN` | 趋势下跌 | MA5<MA20<MA60 + MA20下行 + ADX≥25 + 跌破MA60 | 禁突破 |
| `RANGE_HIGH` | 高位震荡 | 无趋势 + 带内位置 ≥ 0.80 | 只减不增 |
| `RANGE_LOW` | 低位震荡 | 无趋势 + 带内位置 ≤ 0.20 | 箱体低吸 |
| `RANGE_MID` | 中位震荡 | 无趋势 + 其余 | **禁突破** |
| `SQUEEZE` | 极缩量横盘 | 带宽分位 ≤ 0.20 + 口径(近20日振幅/ATR) ≤ 4 + 无趋势 | 观察 |
| `UNKNOWN` | 数据不足 | 指数取数失败或根数不足 | 门控跳过该规则 |

优先级：`PANIC` → `SQUEEZE` → `无趋势(RANGE_*)` → `趋势(TREND_*)` → 兜底 `RANGE_*`。

### 为什么用"双条件"判定趋势

| 指标 | 单独使用的缺陷 |
| --- | --- |
| ADX | 在"缓慢宽幅摆动"里也能读到 30+（实测 `range_mid` 样本 ADX=32），单用会误判成趋势 |
| 穿越次数 | 只反映是否反复穿越中轨，需 ADX 佐证动量强弱 |
| 布林带宽 | **单调趋势的价格序列标准差天然很小、带宽很低** —— 只用带宽做"挤压"判定，任何干净的单边行情都会被误判成横盘（实测踩过这个坑） |

故：**趋势 = ADX 强 且 未反复穿越**；**挤压 = 带宽低 且 口径窄 且 无趋势**。

### 输出示例

```
【维度E - 市场状态雷达】
  📅 判定日期: 2026-09-24  |  指数根数: 250  |  基准: sh000001（上证综指）
  ① 均线结构: 纠缠  (MA5 3925.21 / MA20 3930.15 / MA60 3916.03)
  ② MA中轨斜率(5根): +0.170% → 向上
  ③ ADX(14): 20.09（趋势偏弱）  +DI 21.25 / -DI 34.77
  ③b 近20根穿越MA中轨: 5 次（≥3 视为区间震荡）
  ④ ATR 波动分位: 8%（极低）
  ⑤ 布林带宽分位: 12%（偏低）
  ⑥ 带内位置: 0.21（中轨附近）
  ⑦ 近1日 -1.22%  |  近3日: -1.56%

  🎯 市场状态: RANGE_MID（中位震荡）
  💡 该状态建议的入场逻辑: 主用：均值回归（箱体下沿低吸） | 禁用：突破买入
```

### 对账期重点怀疑的参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `REGIME_ADX_TREND_MIN` | `25.0` | 调高 → 更多行情判为震荡（门控拦得更多） |
| `REGIME_CROSS_TREND_MAX` | `3` | 调低 → 更敏感认定区间震荡 |
| `REGIME_SQUEEZE_CALIBER` | `4.0` | 窄幅压缩门槛 |
| `REGIME_RANGE_HIGH_POS` / `LOW_POS` | `0.80` / `0.20` | 高低位分界 |
| `REGIME_FETCH_TIMEOUT` | `45` | baostock 指数查询冷启动需 20~30s |
| `REGIME_PREFER_SOURCE` | `baostock` | 本机 efinance 常被 TLS 断开，先试它会白等一个超时 |

### 进程内缓存（门控引入的新依赖）

市场状态现有**两个消费方**（门控 + 展示），故加了进程内缓存，键为
`(BENCHMARK_INDEX, 今天日期)`：同一进程只取一次指数（实测 380x 加速），
**只缓存成功结果**，失败路径每次重试。

> ⚠️ 回测/测试若在**同一天**反复注入不同历史切片，必须 `RD._REGIME_CACHE.clear()`，
> 否则所有日期都返回第一次的结果（实测把 867 个交易日全判成 `RANGE_HIGH`，
> 静默毁掉状态分层）。`backtest.py` 已加护栏：状态只剩一种时**显式报警**。

```bash
uv run python services/calc_indicators/verify_regime.py
```

| 贵州茅台 600519 | **-0.23** |

### 核心修复：基准指数切到标的指数

同一天三个指数给出三种状态（上证→RANGE_LOW / 沪深300→RANGE_LOW / 创业板指→SQUEEZE）。
`--etf` 把 `BENCHMARK_INDEX` 切到标的指数，**维度B 大盘过滤 与 维度E 一起生效**。
内置映射（部分）：510300→`sh000300`、510500→`sh000905`、159915→`sz399006`、510050→`sh000016`。

未收录的 ETF 会**显式提示**"按代码段兜底"并给出所用指数，可用 `-o BENCHMARK_INDEX=...` 纠正。

### ⚠️ 一个被实测推翻的推测（留作教训）

曾以为"ETF 波动小，所以 0.5% 回踩阈值对 ETF 太严"，打算放宽到 1.5%。**实测方向是反的**：

| 标的 | 偏离中位数 | ≤0.5% 占比 | >1.5%（价格在均线上方过远）|
| --- | --- | --- | --- |
| 沪深300ETF | 0.81% | 30% | 7.8% |
| 上证50ETF | 0.69% | 37% | 8.6% |
| 中证500ETF | 1.27% | 20% | **19.8%** |
| 创业板ETF | 1.81% | 16% | **30.2%** |

**0.5% 在宽基ETF 上覆盖 30~37% 交易日，本来就够用**；放宽到 1.5% 会把
"价格在 MA5 上方 1.5%"的**追高日**当作回踩买点。故 **ETF 模式不碰回踩阈值**。

唯一保留的调整：`VOLUME_SURGE_RATIO` 1.5 → **1.25**（实测 ETF 量比 >1.5 仅占 3~7% 交易日，近乎死信号）。

### 不适合用本工具的 ETF（提示按类型准确区分）

| --- | --- | --- |
| 债券/货币 | 511990 华宝添益 | 实测日涨跌 **+0.01%**，信号纯噪声 |

| 口径 | 数量 | 占比 |
| --- | --- | --- |
| 2016-01-01 起仍在市的真股票 | **2810 只** | — |
| 其中**区间内退市** | **232 只** | **8.3%** |
| 回测开始前就已退市（已排除） | 89 只 | 区间内无数据 |

等距抽样（`步长=9`）自动按比例纳入约 20 只退市股 —— 实测样本里包含
`退市美都`、`中弘退`、`众和退`、`*ST搜特`、`*ST蓝光` 等真实归零案例。
**手挑样本等于把这 8.3% 全部丢掉，而那恰是"逆势抄底"最可能归零的一批。**

选样规则（`universe.py`，确定性可复现）：

1. baostock 全量清单筛 `type=1`，再用代码段限定真股票

2. 取**在回测区间内真实存在过**者：`ipo_date ≤ start` 且（仍在市 或 `out_date ≥ start`）
3. 按代码排序等距抽样 N 只（`--offset` 换相位做稳健性检验）
4. 结果落盘 `data/cache/calc_indicators/universe.json`，样本可审计

### 判定逻辑（维度通过数优先）

| 层级 | 比较项   | 说明                                        |
| -- | ----- | ----------------------------------------- |
| 1  | 维度通过数 | A/B/C 三维度通过数多者优先（如 2/3 > 1/3）             |
| 2  | 盈亏比   | 通过数相同时，维度C盈亏比高者优先（∞ 视为最大）                 |
| 3  | 动量信号数 | 盈亏比也相同时，有效动量信号数多者优先（MACD金叉/柱线翻红/RSI超卖/放量） |
| 4  | 结构信号  | 动量信号数也相同时，维度A通过者优先                        |
| 5  | 平局    | 以上全部相同时，默认选第一只                            |

## 注意事项

- 数据来源：**只用 baostock，任何情况下都不调用东方财富系数据源**
  （akshare / efinance / adata）。原因（实测）：

  | 事实 | 后果 |
  | --- | --- |
  | 东财走 `push2his.eastmoney.com`，本机**间歇性可用**（同一命令时而成功、时而 `RemoteDisconnected`；curl 直连恒 200） | 不可作为可靠数据源 |
  | 其调用在半挂起时**无超时、会无限阻塞** | 实测把 300 只的回测**卡在 8/300 上约 11 分钟** |
  | 混用来源会导致复权口径/行数不一致（efinance 还会**忽略传入日期范围**返回全量） | 回测区间被悄悄放大 |

  宁可让某只标的**显式取数失败**并记录下来，也不引入不可控的阻塞与来源不一致。
  baostock 单源实测足够：300 只 × 10 年 **761,697 行、0 空文件**。
- 单次查询有**硬超时**（`DEFAULT_SOURCE_TIMEOUT=20s`）：半挂起的 socket 必须从外层掐断，
  否则整个批量任务会卡死。
- **限流实测**（2026-09）：baostock 串行 + 0.6s 间隔，**连续 80 次请求零失败**
  （两批各 40 只 × 10 年，2.6~3.5s/只）。但**无间隔快速连拉 30 只会被挂起** ——
  限流保护必要，不可去掉。
- **回测务必走 `data_layer.py` 的本地缓存**（拉一次、存本地、反复用）。

- 大盘指数：默认上证综指 `sh000001`，可改 `sz399001` / `sh000300`

- 运行时间：约 4-6 秒（网络取决于数据源）

- 数据仅供学习参考，不构成投资建议
