# 基于AkShare的财经新闻采集与报告生成系统需求文档（个人版）

## 一、项目定位与核心原则

### 1.1 项目目标

构建一套轻量级的财经新闻自动化采集工具，专注于个股相关资讯、公司公告及市场突发快讯。数据用于个人生成每日/周期性的新闻简报或复盘报告，不涉及宏观因子建模。

### 1.2 核心铁律（不可违背）

- **原文一字不改**：标题和正文必须保留抓取时的原始文本，禁止任何改写、润色、摘要化处理。
- **日期为核心索引**：以发布日期（精确到天）作为排序、回测对比的首要依据。
- **股票代码自动标注**：若原文提及具体股票名称或代码，必须通过正则或本地映射表预先提取并标记。
- **采集与报告解耦**：采集层只负责抓取与标注原始数据落盘；报告层基于已落盘数据生成，互不阻塞。
- **批处理模式**：单次执行跑完即退，不驻留进程，符合项目"所有脚本 batch 模式"约定。

## 二、数据需求（精简版）

### 2.1 硬性元数据（ID与日期）

| 字段名           | 类型     | 必填 | 说明                                                         |
| ---------------- | -------- | ---- | ------------------------------------------------------------ |
| `news_id`        | string   | ✅   | 唯一标识，建议 `{source}_{date}_{title_hash}`（title_hash 取标题 SHA1 前 8 位，用于去重） |
| `source_url`     | string   | ✅   | 原文链接，用于溯源与去重                                     |
| `source_channel` | string   | ✅   | 来源：`cls`(财联社) / `sina`(新浪财经) / `juchao`(巨潮资讯) / `em`(东方财富) |
| `publish_date`   | date     | ✅   | 仅精确到日（如 `2026-08-17`），满足个人复盘与报告生成即可    |
| `crawl_timestamp`| datetime | 可选 | 内部记录抓取时间点，非强制                                   |

### 2.2 原始文本与股票标注（Fact）

| 字段名           | 类型   | 必填 | 说明                                                         |
| ---------------- | ------ | ---- | ------------------------------------------------------------ |
| `title`          | string | ✅   | 原文标题，一字不改                                           |
| `content`        | string | ✅   | 原文正文，一字不改                                           |
| `mentioned_codes`| list   | 推荐 | 如 `["000001", "600519"]`，由正则或本地库提取（6位数字 + 沪深前缀校验） |
| `mentioned_names`| list   | 推荐 | 如 `["平安银行", "贵州茅台"]`，与 `mentioned_codes` 一一对应 |

### 2.3 字段层级约定

- **元数据（2.1）**：采集层必填，作为主键与索引，缺字段则丢弃该条。
- **原始文本（2.2）**：`title`/`content` 必填且不可改写；`mentioned_codes`/`mentioned_names` 推荐填，提取失败时置空列表，不阻断落盘。
- **扩展字段**：后续如需补充（如 `category`、`sentiment`），追加到 Fact 层，不得回填改写已有字段。

## 三、数据源接口清单（剔除宏观后）

仅保留以下与市场交易直接相关的资讯接口，全部来自 AkShare，不再依赖 Playwright 抓取（与项目 `crawler_news` 现有实现不同，需重构）。

| 接口函数                                   | 数据源     | 覆盖内容                         | 优先级   |
| ------------------------------------------ | ---------- | -------------------------------- | -------- |
| `stock_info_global_cls()`                  | 财联社     | 盘中快讯、突发电报               | ⭐⭐⭐ 最高 |
| `stock_zh_a_news()`                        | 新浪财经   | A股个股动态新闻                  | ⭐⭐⭐ 最高 |
| `stock_zh_a_disclosure_report_cninfo()`    | 巨潮资讯   | 上市公司正式公告（年报/季报/临时公告） | ⭐⭐⭐ 最高 |
| `stock_info_global_em()`                   | 东方财富   | 泛财经资讯、行业动态             | ⭐⭐ 中   |
| `stock_news_em()`                          | 东方财富   | 特定股票相关新闻                 | ⭐⭐ 中   |

### 3.1 接口调用约束

- **限频保护**：每个接口调用间隔 ≥ 2 秒（与 `bankuai-service` 的 zzshare 限频策略一致），避免被源站封禁。
- **超时保护**：单个接口请求超时 300 秒（与项目"单任务 300s"约定一致），超时则记录日志并降级跳过。
- **失败降级**：任一接口失败不阻断整体流程，记录错误日志后继续下一个接口，最终汇总失败列表。
- **字段容错**：AkShare 各接口返回列名可能因版本/源站调整而变化，采集层需对列名做白名单匹配（参考 `macro-data-service` 的列名校验经验），缺失列填空值不报错。

### 3.2 股票标注策略

- **正则提取**：从 `title` + `content` 中用正则 `\b(6\d{5}\|0\d{5}\|3\d{5})\b` 提取 6 位股票代码，并按沪深规则校验（6 开头上交所、0/3 开头深交所）。
- **本地映射表**：维护一份 `data/stock_mapping.json`（code ↔ name 双向），用于从股票名称反查代码。映射表可由 `bankuai-service` 的板块扫描结果沉淀，或手动维护。（注：`data/` 为项目根共用目录，与其他 service 共享）
- **优先级**：正则直接命中的代码优先；未命中代码但命中本地映射表中的名称时，通过名称反查补全。
- **去重**：同一新闻内同一代码多次提及只保留一次。

## 四、数据存储与报告生成

### 4.1 存储方案（轻量化）

- **格式**：JSON Lines（每行一条新闻），按"源-日期"归档存储。JSON 优于 CSV，因为正文可能含逗号/换行，且便于后续追加字段。
- **目录结构**（项目根共用 data/，新闻数据存入 news/ 子目录）：

```
./data/
  raw/
    news/
      2026-08/
        cls_2026-08-17.json       # 财联社当日快讯
        sina_2026-08-17.json      # 新浪财经当日新闻
        juchao_2026-08-17.json    # 巨潮资讯当日公告
        em_global_2026-08-17.json # 东方财富泛资讯
        em_stock_2026-08-17.json  # 东方财富个股新闻
  reports/
    news/
      ...（见 4.2 报告输出）
  stock_mapping.json              # 股票代码↔名称映射表
```

- **文件命名**：`{source_short}_{publish_date}.json`，按日切分，便于按日期回测对比。
- **去重策略**：以 `news_id`（`{source}_{date}_{title_hash}`）为主键，同日同源重复抓取时跳过已存在记录（幂等写入）。
- **保留周期**：永久保留原始 JSON，个人硬盘占用极小（纯文本）。历史数据用于"对比几个月数据"的复盘需求。

### 4.2 报告生成（核心输出）

- **输入**：指定日期范围（如 `2026-06-01` 至 `2026-08-17`），通过 `--start-date` / `--end-date` 参数传入。
- **输出格式**：Markdown 简报（默认）或 HTML 简报（`--format html`）。Markdown 优先，便于版本管理与 diff。
- **报告内容**：
  1. **时间线视图**：按 `publish_date` 升序排列的重大事件/快讯，每条含日期、标题、来源、原文链接。
  2. **股票聚类视图**：按 `mentioned_codes` 聚类，如"贵州茅台(600519) 期间出现 X 条相关公告"，展开为列表。
  3. **突发事件跟踪**：对同一突发主题（标题关键词聚类）的首次报道时间与后续跟踪报道对比，呈现事件演化时间线。
- **输出路径**：`data/reports/news/{start}_{end}_report.{md|html}`，与项目其他报告（`data/reports/`）统一归档。

## 五、工程约束（对齐项目约定）

### 5.1 运行接口

- `main.py` 必须支持 `argparse`，参数：
  - `--date YYYY-MM-DD`：采集指定日期新闻（默认昨天，与项目其他服务一致）。
  - `--symbol 600519`：可选，仅采集与指定股票相关的新闻（透传给 `stock_news_em` 等支持个股过滤的接口）。
  - `--source cls|sina|juchao|em`：可选，指定单一数据源（默认全量）。
- 采集与报告分离为两个入口或两个子命令（`crawl` / `report`），避免混用。

### 5.2 错误处理

- 所有 `main` 入口包含 try-except，捕获异常并记录日志，非零退出码。
- 日志按日切分写入 `logs/` 目录，含任务开始/结束分隔符（与项目日志规范一致）。

### 5.3 依赖管理

- `pyproject.toml` 的 `dependencies` 新增 `akshare>=1.12`，移除或保留 `playwright`（Playwright 仅在 AkShare 无对应接口时作降级抓取）。
- `package = false`（uv Workspace 虚拟成员约定），运行时依赖须在根 `pyproject.toml` 声明。

### 5.4 性能要求

- 单日全源采集总执行时间 < 60 秒（5 个接口 × 2s 限频 + 解析标注，符合项目"总执行时间 1 分钟内"约定）。
- 日期范围报告生成 < 10 秒（纯本地 JSON 读取与聚合）。
